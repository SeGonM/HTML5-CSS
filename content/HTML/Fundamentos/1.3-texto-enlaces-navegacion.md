# 1.3. Texto, enlaces y navegación

En las sesiones anteriores ya aprendimos a organizar un documento, utilizar HTML semántico y reconocer algunas etiquetas de texto. En esta sesión veremos esas etiquetas como un repaso breve y pondremos el foco en una de las capacidades más importantes de la web: enlazar documentos y permitir que una persona se desplace por ellos.

Un enlace no es solo un texto que se puede pulsar. Es una relación entre un punto de origen y un destino. Para que esa relación funcione, debemos escribir correctamente el destino, elegir un texto descriptivo y decidir si lleva a otro documento, a otro sitio o a una parte de la misma página.

## Repaso rápido de texto

Estas etiquetas ya fueron presentadas al trabajar el contenido de `<main>`. Aquí las repasamos para usarlas dentro de los ejemplos de navegación:

```html
<main>
    <h1>Guía de HTML</h1>
    <p>HTML organiza el contenido de una página web.</p>
    <p>
        Esta palabra es <strong>importante</strong> y esta otra lleva
        <em>énfasis</em>.
    </p>
</main>
```

- `<h1>` a `<h6>` organizan los temas según su nivel.
- `<p>` agrupa una idea en un párrafo.
- `<strong>` indica importancia.
- `<em>` indica énfasis.
- `<mark>` destaca un fragmento relevante dentro de un contexto.
- `<small>` contiene información secundaria o aclaraciones.
- `<span>` agrupa texto sin añadir un significado propio.
- `<br>` crea un salto de línea cuando ese salto forma parte del contenido.

No uses estas etiquetas solo para cambiar la apariencia. Si solo necesitas tamaño, color, negrita, cursiva o espacio, esa decisión corresponde a CSS. En esta sesión las usaremos para que los textos de los enlaces y las secciones sean claros.

## Listas: organizar información relacionada

Las listas agrupan varios elementos que tienen relación entre sí. Son importantes porque expresan la estructura del contenido sin depender de viñetas, números, espacios o estilos visuales.

Una lista siempre debe responder a una idea clara: un conjunto de opciones, unos pasos, unas características o una serie de conceptos. Cada elemento de la lista se escribe con `<li>`, que significa *list item* o elemento de lista.

### `<ul>`: listas sin orden

`<ul>` significa *unordered list*, es decir, lista no ordenada. Debes usarla cuando el orden de los elementos no cambia su significado.

```html
<h2>Herramientas del curso</h2>
<ul>
  <li>Editor de código</li>
  <li>Navegador web</li>
  <li>Validador HTML</li>
</ul>
```

Si intercambiamos las herramientas, la información sigue siendo válida. Por eso corresponde una lista no ordenada.

Otros casos habituales para `<ul>` son:

- características de un producto;
- categorías o temas relacionados;
- opciones de navegación;
- recursos disponibles;
- elementos cuya posición no representa una prioridad.

### `<ol>`: listas ordenadas

`<ol>` significa *ordered list*, es decir, lista ordenada. Debes usarla cuando la posición de cada elemento es importante o cuando existe una secuencia que debe seguirse.

```html
<h2>Pasos para crear un documento</h2>
<ol>
  <li>Crear el archivo HTML.</li>
  <li>Escribir la estructura del documento.</li>
  <li>Abrirlo en el navegador.</li>
  <li>Revisar los enlaces.</li>
</ol>
```

Si cambiamos el orden de estos pasos, el proceso puede dejar de tener sentido. Por eso usamos `<ol>`.

Otros casos habituales para `<ol>` son:

- instrucciones paso a paso;
- recetas;
- clasificaciones o posiciones;
- una secuencia temporal;
- prioridades o tareas que deben realizarse en orden.

### No elijas la lista por sus viñetas o números

El navegador suele mostrar viñetas para `<ul>` y números para `<ol>`, pero esa apariencia no es la razón para elegir una u otra. Lo importante es el significado del contenido.

```html
<!-- Aunque quieras quitar los números con CSS, sigue siendo una secuencia -->
<ol>
  <li>Instalar el editor.</li>
  <li>Crear el proyecto.</li>
  <li>Escribir la primera página.</li>
</ol>
```

CSS podrá cambiar las viñetas, los números o incluso ocultarlos. Aun así, el navegador y las tecnologías de asistencia seguirán entendiendo si la lista tiene orden o no.

### `<li>` siempre debe pertenecer a una lista

No uses `<li>` directamente dentro de `<main>`, `<section>` o `<nav>`. Un `<li>` debe estar dentro de `<ul>`, `<ol>` o, en casos específicos, de una lista de definición.

```html
<!-- Correcto -->
<ul>
  <li>HTML</li>
  <li>CSS</li>
</ul>

<!-- Incorrecto: falta el contenedor de la lista -->
<li>HTML</li>
<li>CSS</li>
```

Una lista también puede contener otros elementos, como enlaces, párrafos o incluso otra lista:

```html
<ul>
  <li>
    HTML
    <ul>
      <li>Estructura</li>
      <li>Semántica</li>
    </ul>
  </li>
  <li>CSS</li>
</ul>
```

La lista anidada pertenece al elemento padre correspondiente. La indentación ayuda a ver esa relación y evita confundir qué elementos están al mismo nivel.

## ¿Por qué las listas son importantes dentro de `<nav>`?

Una navegación está formada por un conjunto de destinos relacionados. La forma más clara y habitual de representarla es colocar los enlaces dentro de una lista:

```html
<nav aria-label="Navegación principal">
  <ul>
    <li><a href="index.html">Inicio</a></li>
    <li><a href="fundamentos/1.1-estructura-documento-html.md">Estructura</a></li>
    <li><a href="fundamentos/1.2-html-semantico.md">HTML semántico</a></li>
    <li><a href="fundamentos/1.3-texto-enlaces-navegacion.md">Enlaces</a></li>
  </ul>
</nav>
```

Esta estructura comunica tres niveles de información:

1. `<nav>` indica que el bloque es una navegación importante.
2. `<ul>` indica que contiene un conjunto de opciones sin un orden obligatorio.
3. Cada `<li>` representa una opción y cada `<a>` define su destino.

El orden visual de los enlaces puede ser útil, pero normalmente no significa que la persona deba visitar “Inicio” antes que “HTML semántico”. Por eso una navegación suele utilizar `<ul>` y no `<ol>`.

### ¿Cuándo usar `<ol>` dentro de `<nav>`?

Usa `<ol>` si la navegación representa una secuencia o posiciones con significado. Por ejemplo, un índice de pasos que deben seguirse en orden:

```html
<nav aria-label="Pasos del ejercicio">
  <ol>
    <li><a href="#preparar">Preparar los archivos</a></li>
    <li><a href="#escribir">Escribir el HTML</a></li>
    <li><a href="#probar">Probar los enlaces</a></li>
  </ol>
</nav>
```

En este caso, el número del paso aporta información. Si solo estás mostrando las secciones de una página o las páginas de un curso, usa `<ul>`.

### Listas sin estilos siguen siendo listas

No conviertas un grupo de enlaces en párrafos separados solo porque más adelante quieres quitar las viñetas con CSS. El HTML debe conservar el significado:

```html
<!-- Buena base para una navegación horizontal o vertical -->
<nav aria-label="Secciones del curso">
  <ul>
    <li><a href="#html">HTML</a></li>
    <li><a href="#css">CSS</a></li>
  </ul>
</nav>
```

Más adelante CSS podrá mostrar esa lista en una fila, quitar las viñetas o cambiar su separación. La presentación puede cambiar; la estructura semántica debe mantenerse.

## ¿Qué es un enlace?

El elemento `<a>` crea un enlace. Su atributo principal es `href`, que indica el destino:

```html
<a href="destino.html">Visitar el documento</a>
```

En este ejemplo:

- `<a>` es el elemento de enlace;
- `href="destino.html"` contiene la dirección del destino;
- `Visitar el documento` es el texto visible y seleccionable.

El texto del enlace debe explicar a dónde lleva. Evita textos aislados como “haz clic aquí”, “ver más” o “seguir leyendo”, porque pierden información cuando una persona recorre únicamente la lista de enlaces.

```html
<!-- Poco descriptivo -->
<a href="contacto.html">Haz clic aquí</a>

<!-- Más claro -->
<a href="contacto.html">Contactar con el equipo</a>
```

## Rutas relativas

Una ruta relativa describe un destino tomando como punto de partida la ubicación del archivo actual. Es la forma más habitual de enlazar archivos que pertenecen al mismo proyecto.

Imagina esta estructura:

```text
proyecto/
├── index.html
├── pages/
│   └── contacto.html
└── docs/
    └── html/
        └── estructura.html
```

### Desde `index.html`

Como `index.html` está en la raíz, para llegar a `pages/contacto.html` avanzamos hacia la carpeta `pages`:

```html
<a href="pages/contacto.html">Contacto</a>
```

También se puede escribir `./pages/contacto.html`. El prefijo `./` significa “desde la carpeta actual” y es opcional en este caso:

```html
<a href="./pages/contacto.html">Contacto</a>
```

### Desde `contacto.html`

`contacto.html` ya está dentro de `pages`. Para volver a la raíz usamos `..`, que significa “subir una carpeta”:

```html
<a href="../index.html">Volver al inicio</a>
```

Después de subir a la raíz, podemos entrar en `docs/html`:

```html
<a href="../docs/html/estructura.html">Ver la documentación</a>
```

La ruta se calcula desde la carpeta del archivo que contiene el enlace, no desde la raíz del proyecto ni desde la ubicación que vemos en el explorador.

### Desde una carpeta más profunda

Si el archivo actual es `docs/html/estructura.html` y queremos enlazar con `index.html`, debemos subir dos niveles:

```html
<a href="../../index.html">Volver al inicio</a>
```

Cada `..` sube una carpeta:

```text
docs/html/estructura.html
    ..  -> docs/
    ../.. -> proyecto/
```

### Reglas para evitar errores

- Escribe las rutas desde la ubicación del archivo actual.
- Usa `/` para separar carpetas, incluso si trabajas en Windows.
- Respeta mayúsculas y minúsculas en nombres de archivos y carpetas; algunos servidores las distinguen.
- Evita espacios y caracteres extraños en los nombres de archivos.
- Comprueba que el nombre y la extensión coincidan exactamente.
- No escribas una ruta del ordenador como `C:\Users\...`; esa ruta no funcionará para otras personas.

Un enlace roto suele deberse a una carpeta omitida, un `..` de más o de menos, una extensión incorrecta o una diferencia entre mayúsculas y minúsculas.

## Rutas absolutas y URLs absolutas

Una URL absoluta contiene toda la dirección necesaria para encontrar un recurso en la web. Empieza normalmente por un protocolo como `https://`:

```html
<a href="https://developer.mozilla.org/es/docs/Web/HTML">
  Consultar la referencia de HTML en MDN
</a>
```

Este enlace funcionará desde cualquier página porque no depende de la carpeta donde esté el archivo actual.

Una ruta relativa, en cambio, depende de la ubicación del archivo:

```html
<a href="../../docs/html/estructura.html">
  Consultar la documentación del proyecto
</a>
```

### Diferencia práctica

| Tipo | Ejemplo | Depende de la ubicación del archivo |
| --- | --- | --- |
| Relativa | `../docs/tema.html` | Sí |
| URL absoluta | `https://ejemplo.com/docs/tema` | No |

Usa rutas relativas para archivos del mismo proyecto. Así los enlaces continúan funcionando si el proyecto se mueve a otro ordenador, repositorio o dominio.

Usa una URL absoluta para enlazar con otro sitio web:

```html
<a href="https://html.spec.whatwg.org/">
  Leer la especificación de HTML
</a>
```

No confundas una URL absoluta con una ruta que comienza con `/`:

```html
<a href="/contacto.html">Contacto</a>
```

Esta es una ruta desde la raíz del sitio o del servidor. No es una URL completa y puede comportarse de forma diferente cuando abres un archivo directamente desde el ordenador. Para los ejercicios de este repositorio, las rutas relativas suelen ser la opción más segura.

## Enlaces dentro de la misma página

También podemos enlazar con una sección concreta del documento. Para hacerlo necesitamos dos piezas:

1. un `id` único en el elemento de destino;
2. un `href` que empiece por `#` y contenga ese mismo `id`.

```html
<nav aria-label="Índice de la página">
  <a href="#estructura">Estructura</a>
  <a href="#rutas">Rutas</a>
  <a href="#practica">Práctica</a>
</nav>

<main>
  <section id="estructura">
    <h2>Estructura de los enlaces</h2>
    <p>Un enlace relaciona un origen con un destino.</p>
  </section>

  <section id="rutas">
    <h2>Rutas relativas y absolutas</h2>
    <p>Las rutas indican cómo encontrar un documento.</p>
  </section>

  <section id="practica">
    <h2>Práctica</h2>
    <p>En esta sección pondrás a prueba la navegación.</p>
  </section>
</main>
```

Cuando la persona selecciona `#rutas`, el navegador busca el elemento que tiene `id="rutas"` y desplaza la página hasta él. El `#` no forma parte del valor del `id`; solo indica que el enlace apunta a un fragmento de la misma página.

### Reglas para usar `id`

- El valor debe ser único dentro del documento.
- No uses espacios; utiliza nombres claros como `recursos-html`.
- El texto después de `#` debe coincidir exactamente con el `id`.
- El `id` debe identificar el destino, no el enlace de origen.

```html
<!-- Correcto -->
<a href="#recursos-html">Ir a los recursos</a>
<section id="recursos-html">
  <h2>Recursos HTML</h2>
</section>

<!-- Incorrecto: no coinciden -->
<a href="#recursos">Ir a los recursos</a>
<section id="recursos-html">
  <h2>Recursos HTML</h2>
</section>
```

## Enlaces a una sección de otro documento

Un fragmento también puede combinarse con una ruta. Primero se escribe el archivo y después `#id`:

```html
<a href="../guia.html#atributos">
  Ver la sección de atributos
</a>
```

Este enlace abre `guia.html` y luego busca dentro de ese documento el elemento cuyo `id` sea `atributos`.

También funciona con una URL absoluta:

```html
<a href="https://developer.mozilla.org/es/docs/Web/HTML#conceptos_y_sintaxis">
  Ir a conceptos y sintaxis en MDN
</a>
```

## `<nav>` para organizar la navegación

`<nav>` identifica un bloque de enlaces de navegación importante. No reemplaza a los enlaces ni crea destinos automáticamente: sirve para agruparlos y describir su propósito.

Una navegación principal puede enlazar con diferentes documentos:

```html
<header>
  <h1>Curso de HTML</h1>

  <nav aria-label="Navegación principal">
    <a href="index.html">Inicio</a>
    <a href="fundamentos/1.1-estructura-documento-html.md">
      Estructura
    </a>
    <a href="fundamentos/1.2-html-semantico.md">
      HTML semántico
    </a>
    <a href="fundamentos/1.3-texto-enlaces-navegacion.md" aria-current="page">
      Enlaces y navegación
    </a>
  </nav>
</header>
```

Un índice de la misma página también es navegación, aunque sus enlaces usen fragmentos:

```html
<nav aria-label="Índice de esta sesión">
  <ul>
    <li><a href="#repaso-texto">Repaso de texto</a></li>
    <li><a href="#rutas-relativas">Rutas relativas</a></li>
    <li><a href="#rutas-absolutas">Rutas absolutas</a></li>
    <li><a href="#enlaces-internos">Enlaces internos</a></li>
  </ul>
</nav>
```

Puedes tener más de un `<nav>` en una página, pero cada bloque debe tener un propósito claro. Usa `aria-label` para diferenciarlos cuando sea necesario:

```html
<nav aria-label="Navegación principal">...</nav>
<nav aria-label="Índice de esta sesión">...</nav>
```

`aria-current="page"` indica cuál es el enlace que representa la página actual. En una navegación de documentos, solo debe aparecer en el enlace activo. Para un índice interno, el objetivo es una sección y no se debe marcar toda la lista como página actual.

### ¿Cuándo no usar `<nav>`?

No todos los enlaces necesitan estar dentro de `<nav>`:

```html
<p>
  Puedes consultar
  <a href="https://developer.mozilla.org/es/">la documentación de MDN</a>
  para ampliar el tema.
</p>
```

Este enlace forma parte de un párrafo y no es un bloque de navegación. `<nav>` está pensado para grupos de enlaces que ayudan a desplazarse por un sitio, una sección o un documento.

## Abrir enlaces en otra pestaña

Por defecto, un enlace se abre en la misma pestaña. Si existe una razón para abrirlo en otra pestaña, se puede usar `target="_blank"`:

```html
<a
  href="https://developer.mozilla.org/es/"
  target="_blank"
  rel="noopener"
>
  Consultar MDN en otra pestaña
</a>
```

Ten en cuenta lo siguiente:

- abrir otra pestaña cambia el comportamiento esperado del enlace;
- conviene avisar en el texto del enlace cuando sea relevante;
- `rel="noopener"` evita que el documento nuevo controle la ventana de origen;
- no uses `target="_blank"` para todos los enlaces.
