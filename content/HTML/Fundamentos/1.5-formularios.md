# 1.5. Formularios

Los formularios permiten que una persona envíe información: registrarse, buscar contenido, solicitar contacto o completar una compra. Un formulario bien construido explica qué dato solicita, utiliza el control adecuado y permite corregir errores.

En esta sesión integraremos elementos vistos anteriormente, como `<main>`, `<section>`, `<h1>`, `<p>`, `<strong>` y `<a>`, junto con nuevos controles específicos para formularios.

## 1. El elemento `<form>`

`<form>` es el contenedor semántico de los controles que se enviarán juntos. Sus atributos principales son:

- `action`: dirección a la que se enviará el formulario. En este curso puedes usar una ruta de ejemplo para practicar.
- `method`: forma en que se prepara el envío. `get` muestra los datos en la dirección de la página y `post` los envía sin mostrarlos en la dirección. Por ahora, quédate con esta diferencia básica.
- `autocomplete`: permite que el navegador ayude a completar datos conocidos.

```html
<main>
  <section aria-labelledby="registro-titulo">
    <h1 id="registro-titulo">Crear una cuenta</h1>
    <p>Los campos marcados con <strong>obligatorio</strong> deben completarse.</p>

    <form action="/registro" method="post" autocomplete="on">
      <!-- controles del formulario -->
    </form>

    <p><a href="/privacidad">Consulta nuestra política de privacidad.</a></p>
  </section>
</main>
```

`<main>`, `<section>`, `<h1>`, `<p>`, `<strong>` y `<a>` ya fueron estudiados. Aquí aportan estructura, jerarquía, información y navegación alrededor del formulario. Un documento debe tener un solo `<main>`, pero puede contener varias secciones.

## 2. `<label>` e `<input>`

`<label>` identifica un control y permite que una persona sepa qué información debe escribir. La asociación explícita se realiza haciendo coincidir `for` del label con `id` del input.

`<input>` es un control vacío que cambia de comportamiento según su atributo `type`. `name` identifica el dato cuando se prepara el formulario para enviarlo y debe estar presente en los campos que quieras incluir.

```html
<label for="nombre">Nombre completo</label>
<input id="nombre"
       name="nombre"
       type="text"
       autocomplete="name"
       required>
```

Al pulsar el texto “Nombre completo”, el foco pasa al campo asociado. También existe una asociación implícita colocando el control dentro del label, pero la asociación explícita suele ser más clara:

```html
<label>
  Acepto recibir novedades
  <input type="checkbox" name="novedades" value="si">
</label>
```

No uses `placeholder` como reemplazo de un label: desaparece al escribir y no identifica permanentemente el campo.

## 3. Tipos de `input` más utilizados

El tipo correcto mejora el teclado del móvil, la validación inicial y la experiencia de uso.

| Tipo | Uso habitual | Ejemplo |
|---|---|---|
| `text` | Nombres, títulos y textos cortos | `<input type="text">` |
| `email` | Una o varias direcciones de correo | `<input type="email">` |
| `password` | Contraseñas | `<input type="password">` |
| `search` | Consultas de búsqueda | `<input type="search">` |
| `tel` | Teléfonos | `<input type="tel">` |
| `url` | Direcciones web | `<input type="url">` |
| `number` | Cantidades realmente numéricas | `<input type="number">` |
| `date` | Una fecha sin hora | `<input type="date">` |
| `checkbox` | Opciones independientes | `<input type="checkbox">` |
| `radio` | Una opción dentro de un grupo | `<input type="radio">` |
| `file` | Seleccionar archivos | `<input type="file">` |
| `submit` | Enviar el formulario | `<input type="submit">` |

### Ejemplo integrado

```html
<form action="/perfil" method="post">
  <label for="correo">Correo electrónico</label>
  <input id="correo" name="correo" type="email"
         autocomplete="email" required>

  <label for="clave">Contraseña</label>
  <input id="clave" name="clave" type="password"
         minlength="8" autocomplete="new-password" required>

  <label for="sitio">Sitio web</label>
  <input id="sitio" name="sitio" type="url"
         placeholder="https://ejemplo.com">

  <button type="submit">Guardar perfil</button>
</form>
```

`<button>` es un elemento de botón y se explica más adelante. `type="submit"` hace que envíe el formulario. En un formulario puede haber varios botones, por lo que conviene declarar siempre su tipo.

### Contraseñas y archivos

`password` oculta visualmente lo escrito mientras lo tecleas. No lo uses para información que no deba compartirse y recuerda que este tipo solo cambia la forma en que se muestra el texto.

`file` abre el selector de archivos del dispositivo. `accept` sugiere qué formatos elegir:

```html
<label for="avatar">Foto de perfil</label>
<input id="avatar" name="avatar" type="file"
       accept="image/png, image/jpeg, image/webp">
```

`accept` ayuda a elegir archivos del tipo indicado, pero no reemplaza la revisión del archivo. Para permitir varios archivos se puede añadir `multiple`.

## 4. Tipos menos frecuentes o especializados

Estos tipos son válidos, pero dependen del contexto y no aparecen en todos los formularios:

| Tipo | Para qué sirve | Consideración |
|---|---|---|
| `color` | Elegir un color | No sustituye una paleta accesible ni garantiza un formato concreto. |
| `time` | Elegir una hora | El formato visible depende del navegador y la configuración regional. |
| `datetime-local` | Fecha y hora local | No incluye zona horaria. |
| `month` | Elegir un mes y año | Útil para periodos, no para una fecha exacta. |
| `week` | Elegir una semana del año | Poco común fuera de calendarios o planificación. |
| `range` | Elegir un valor aproximado en un intervalo | No muestra con claridad el valor si no se acompaña de texto. |
| `hidden` | Enviar un valor no visible | No es un control para la persona; nunca debe guardar secretos. |
| `reset` | Restablecer valores iniciales | Puede borrar datos accidentalmente; úsalo con mucha precaución. |
| `button` | Botón sin envío automático | Se puede usar más adelante para otras acciones. |
| `image` | Botón de envío representado por una imagen | Es poco habitual; un `<button>` suele ser más flexible y accesible. |

### Ejemplos

```html
<label for="color">Color preferido</label>
<input id="color" name="color" type="color" value="#2563eb">

<label for="hora">Hora de la cita</label>
<input id="hora" name="hora" type="time">

<label for="volumen">Volumen</label>
<input id="volumen" name="volumen" type="range"
       min="0" max="100" value="50">
```

`color` muestra un selector del sistema, pero no debes depender solo del color para comunicar estados. `range` es apropiado para preferencias aproximadas, como volumen o intensidad; para un valor exacto suele ser mejor `number`.

## 5. `<textarea>` para textos largos

`<textarea>` permite escribir varias líneas. A diferencia de `<input>`, tiene contenido entre su etiqueta de apertura y cierre, aunque normalmente empieza vacío:

```html
<label for="mensaje">Mensaje</label>
<textarea id="mensaje"
          name="mensaje"
          rows="6"
          maxlength="500"
          placeholder="Escribe tu consulta"></textarea>
```

- `rows` sugiere la altura inicial.
- `maxlength` limita la cantidad de caracteres.
- `placeholder` es una pista opcional, no una etiqueta.

## 6. Agrupar controles con `<fieldset>` y `<legend>`

`<fieldset>` agrupa controles relacionados. `<legend>` proporciona el título visible y accesible de ese grupo. Son especialmente importantes para radios y casillas:

```html
<fieldset>
  <legend>¿Cómo prefieres que te contactemos?</legend>

  <label>
    <input type="radio" name="contacto" value="email" required>
    Correo electrónico
  </label>
  <label>
    <input type="radio" name="contacto" value="telefono">
    Teléfono
  </label>
</fieldset>
```

Todos los radios tienen el mismo `name`, por eso solo se puede elegir uno. Los checkboxes pueden compartir nombre cuando se permiten varias opciones:

```html
<fieldset>
  <legend>Temas de interés</legend>
  <label><input type="checkbox" name="temas" value="html"> HTML</label>
  <label><input type="checkbox" name="temas" value="css"> CSS</label>
</fieldset>
```

`value` es el valor que identifica la opción, no necesariamente el texto visible. No uses un grupo de radios si la persona puede elegir varias respuestas.

## 7. `<select>`, `<option>` y `<optgroup>`

`<select>` crea una lista de opciones. Cada opción se escribe con `<option>`, que tiene un `value` para identificarla y un texto visible:

```html
<label for="nivel">Nivel de experiencia</label>
<select id="nivel" name="nivel" required>
  <option value="">Selecciona un nivel</option>
  <option value="inicial">Inicial</option>
  <option value="intermedio">Intermedio</option>
  <option value="avanzado">Avanzado</option>
</select>
```

La primera opción vacía funciona como instrucción y obliga a elegir otra cuando se usa `required`. `<optgroup>` agrupa opciones bajo un título:

```html
<label for="curso">Curso</label>
<select id="curso" name="curso">
  <optgroup label="HTML">
    <option value="estructura">Estructura</option>
    <option value="formularios">Formularios</option>
  </optgroup>
  <optgroup label="CSS">
    <option value="selectores">Selectores</option>
  </optgroup>
</select>
```

Usa radios cuando hay pocas opciones visibles y select cuando la lista es más extensa o debe ocupar menos espacio.

## 8. `<datalist>` para sugerencias

`<datalist>` proporciona sugerencias para un `<input>` sin limitar la posibilidad de escribir otro valor. El atributo `list` del input debe coincidir con el `id` del datalist:

```html
<label for="editor">Editor favorito</label>
<input id="editor" name="editor" list="editores">

<datalist id="editores">
  <option value="Visual Studio Code">
  <option value="Zed">
  <option value="Vim">
</datalist>
```

`<datalist>` no reemplaza a `<select>`: la persona puede escribir una opción que no esté en la lista. Si solo se permiten valores concretos, utiliza `<select>`.

## 9. `<button>` y sus tipos

`<button>` crea un botón que puede contener texto y otros elementos inline. Dentro de un formulario, su tipo por defecto puede ser `submit`, por eso conviene declararlo:

```html
<button type="submit">Enviar formulario</button>
<button type="reset">Limpiar campos</button>
<button type="button">Mostrar ayuda</button>
```

- `submit` envía el formulario.
- `reset` devuelve los controles a sus valores iniciales; úsalo solo si realmente ayuda.
- `button` no envía nada y queda disponible para una interacción posterior.

Un botón debe tener un texto claro y ser activable con teclado. No uses un `<div>` como sustituto de `<button>`.

## 10. Ayuda, errores y accesibilidad

`aria-describedby` relaciona un control con un texto de ayuda. El valor debe coincidir con el `id` del elemento que contiene esa explicación:

```html
<label for="usuario">Nombre de usuario</label>
<input id="usuario"
       name="usuario"
       type="text"
       minlength="3"
       maxlength="20"
       pattern="[A-Za-z0-9_]+"
       aria-describedby="ayuda-usuario"
       required>
<small id="ayuda-usuario">
  Usa entre 3 y 20 letras, números o guiones bajos.
</small>
```

`<small>` ya fue visto como texto secundario. Aquí contiene una instrucción asociada al campo. `aria-describedby` aporta esa relación a las tecnologías de asistencia, pero no reemplaza al label.

Para un error visible, relaciona el mensaje con el campo y marca su estado:

```html
<label for="correo">Correo electrónico</label>
<input id="correo" name="correo" type="email"
       aria-invalid="true"
       aria-describedby="error-correo"
       required>
<p id="error-correo">Escribe una dirección de correo válida.</p>
```

`aria-invalid="true"` comunica que el valor actual no es válido. La interfaz debe mostrar el error de forma visible y explicar cómo corregirlo.

## 11. Validación HTML5

La validación nativa proporciona una primera capa de ayuda:

- `required`: exige un valor.
- `minlength` y `maxlength`: limitan texto.
- `min` y `max`: limitan números, fechas u horas.
- `step`: define los intervalos permitidos.
- `pattern`: permite indicar un patrón sencillo para los caracteres aceptados.
- `accept`: sugiere formatos de archivo.
- `email`, `url` y otros tipos comprueban formatos básicos.

```html
<label for="cantidad">Cantidad de asistentes</label>
<input id="cantidad" name="cantidad" type="number"
       min="1" max="20" step="1" required>
```

La validación del navegador ayuda a detectar errores mientras se completa el formulario. En esta etapa nos interesa aprender a crear los campos y sus reglas básicas.
