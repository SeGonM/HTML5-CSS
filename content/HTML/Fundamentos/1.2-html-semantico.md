# 1.2. HTML semántico

En la sesión anterior aprendimos a construir un documento HTML y a organizar sus elementos. Ahora damos un paso más: no solo importa que el documento tenga una estructura válida, también importa que esa estructura explique qué representa cada contenido.

El HTML semántico utiliza elementos cuyo nombre comunica su propósito. Un navegador puede mostrar una página aunque esté construida casi por completo con `<div>`, pero las personas, los buscadores y las tecnologías de asistencia tendrán menos información para interpretarla.

## HTML semántico frente a contenedores genéricos

Los contenedores son como cajas más grandes que guardan elementos más pequeños relacionados con ellas, pero no tienen un significado propio. Por ejemplo, `<div>` y `<span>` son contenedores genéricos que no indican qué representa su contenido.

`<div>` y `<span>` no están mal. Son contenedores sin significado propio y son útiles cuando no existe un elemento más específico.

```html
<!-- El contenedor no explica qué representa el contenido -->
<div class="menu">
  ...
</div>

<!-- El elemento indica que contiene navegación -->
<nav aria-label="Navegación principal">
  ...
</nav>
```

La diferencia no está en el aspecto visual. Ambos elementos pueden recibir estilos con CSS. La diferencia está en la información que el HTML proporciona antes de aplicar estilos.

Una pregunta útil antes de elegir una etiqueta es:

> Si elimino las clases y los estilos, ¿el elemento sigue explicando qué tipo de contenido contiene?

Si la respuesta es no, revisa si existe un elemento semántico más apropiado. Si no existe, utiliza `<div>` sin problema.

## Las regiones principales de una página

Los elementos estructurales más importantes forman regiones reconocibles, también llamadas *landmarks*. Estas regiones permiten entender la página y desplazarse por ella con herramientas de asistencia.

```html
<body>
  <header>
    <h1>Academia Web</h1>
    <nav aria-label="Navegación principal">
      ...
    </nav>
  </header>

  <main>
    <h2>Últimos artículos</h2>
    <section>
      ...
    </section>
  </main>

  <footer>
    ...
  </footer>
</body>
```

### `<header>`

Representa contenido introductorio de una página o de una sección. Puede contener un título, una descripción, una identidad visual o navegación relacionada.

No significa necesariamente “la parte superior de la ventana”. También puede aparecer dentro de un `<article>` o de una `<section>` si esa sección tiene su propia introducción.

```html
<article>
  <header>
    <h2>Cómo estudiar HTML</h2>
    <p>Publicado el 7 de septiembre de 2026.</p>
  </header>
  <p>El contenido del artículo comienza aquí.</p>
</article>
```

## Los encabezados: de `<h1>` a `<h6>`

Los encabezados expresan la jerarquía del contenido. HTML ofrece seis niveles, desde `<h1>`, el nivel principal, hasta `<h6>`, el nivel más específico:

```html
<h1>Curso de HTML</h1>
  <h2>Fundamentos</h2>
    <h3>Estructura del documento</h3>
      <h4>El elemento html</h4>
        <h5>El atributo lang</h5>
          <h6>Ejemplos de idiomas</h6>
```

La indentación del ejemplo ayuda a visualizar la relación, pero no crea la jerarquía. La jerarquía la determina el nivel del encabezado y la organización real de las ideas.

### ¿Qué significa cada nivel?

- `<h1>` identifica el tema principal de la página. Normalmente una página tiene un encabezado principal.
- `<h2>` divide el tema principal en secciones importantes.
- `<h3>` divide una sección `<h2>` en apartados más concretos.
- `<h4>`, `<h5>` y `<h6>` permiten continuar esa división cuando el contenido realmente necesita más niveles.

No es necesario utilizar los seis niveles en todos los documentos. Una página sencilla puede necesitar únicamente `<h1>` y `<h2>`.

```html
<h1>Guía de HTML</h1>

<h2>Estructura</h2>
<p>Aprende cómo se organiza un documento.</p>

<h2>Semántica</h2>
<p>Aprende a elegir elementos que describen el contenido.</p>
```

### Reglas para una jerarquía clara

El siguiente encabezado debe corresponder con la relación entre las ideas, no con el tamaño visual que quieres obtener:

```html
<!-- Correcto: cada apartado pertenece al tema anterior -->
<h1>Aprender HTML</h1>
<h2>Elementos</h2>
<h3>Elementos de texto</h3>
<h3>Elementos estructurales</h3>
<h2>Atributos</h2>
```

Evita saltar niveles sin una razón clara:

```html
<!-- Poco recomendable: no hay un h3 que agrupe este h4 -->
<h1>Aprender HTML</h1>
<h4>Elementos de texto</h4>
```

Tampoco uses un encabezado solo para hacer que un texto se vea grande o pequeño. El tamaño, el color y el espacio se controlan con CSS. El encabezado debe elegirse por su importancia y su relación con el resto del contenido.

Los lectores de pantalla pueden mostrar una lista de encabezados para que una persona recorra rápidamente la página. Por eso un encabezado debe ser descriptivo y no debería estar vacío:

```html
<!-- Mejor: explica el contenido que sigue -->
<h2>Recursos para practicar</h2>

<!-- Evitar: no aporta información -->
<h2></h2>
```

El encabezado de una sección puede estar dentro de su propio `<header>`, pero no es obligatorio crear un `<header>` solo para colocar un título:

```html
<section>
  <h2>Conceptos básicos</h2>
  <p>Contenido de la sección.</p>
</section>
```

### Encabezados dentro de regiones y artículos

Cada región puede tener su propia introducción y jerarquía. En este ejemplo, el `<h1>` identifica la página, el `<h2>` identifica la sección y cada `<h3>` identifica un artículo dentro de ella:

```html
<header>
  <h1>Blog de aprendizaje web</h1>
</header>

<main>
  <section>
    <h2>Artículos recientes</h2>

    <article>
      <h3>Cómo empezar con HTML</h3>
      <p>Una introducción para crear tu primer documento.</p>
    </article>

    <article>
      <h3>Qué significa HTML semántico</h3>
      <p>Una guía para elegir elementos con significado.</p>
    </article>
  </section>
</main>
```

La página no tiene que usar `<h1>` dentro de cada `<article>`. El nivel depende de la relación que ese artículo tenga con la página y con la sección que lo contiene.

### `<nav>`

Agrupa un conjunto de enlaces destinados a la navegación. No todo grupo de enlaces necesita `<nav>`: úsalo para bloques importantes, como la navegación principal, el índice de un documento o la navegación entre páginas.

Si una página tiene varios elementos `<nav>`, dales nombres que permitan distinguirlos:

```html
<nav aria-label="Navegación principal">
  ...
</nav>

<nav aria-label="Índice del artículo">
  ...
</nav>
```

La etiqueta `aria-label` no convierte un elemento genérico en navegación; debe acompañar a un `<nav>` que realmente contenga navegación. Los enlaces y sus destinos se estudiarán con más detalle en la siguiente sesión.

### `<main>`

Contiene el contenido principal y único del documento. No debe repetirse varias veces en la misma página ni incluir contenido que se repite en todas las páginas, como la navegación general o el pie común.

En una página normal debe existir un único `<main>`:

```html
<main>
  <h1>Curso de HTML</h1>
  <p>Contenido principal de esta página.</p>
</main>
```

Que un elemento sea importante no significa que deba estar dentro de `<main>`. La navegación global puede ser importante y aun así pertenece al `<header>`.

### Etiquetas básicas de texto dentro de `<main>`

Una vez definida la región principal, el contenido necesita elementos que expliquen qué tipo de texto contiene. No todo debe escribirse como texto suelto dentro de `<div>`.

#### `<p>`: párrafos

`<p>` agrupa una idea o bloque de texto. Cuando una idea cambia, normalmente comienza otro párrafo:

```html
<main>
  <h1>Aprender HTML</h1>
  <p>HTML permite organizar el contenido de una página.</p>
  <p>Una estructura clara facilita la lectura y el mantenimiento.</p>
</main>
```

No uses varios `<br>` para separar párrafos ni dejes texto directamente dentro de `<main>` sin un elemento que lo describa. El espaciado visual se resolverá más adelante con CSS.

#### `<strong>` y `<em>`: significado del texto

`<strong>` indica que un texto tiene una importancia especial:

```html
<p><strong>Importante:</strong> guarda siempre una copia de tu trabajo.</p>
```

`<em>` indica énfasis dentro de una frase:

```html
<p>HTML describe el contenido, <em>no su apariencia</em>.</p>
```

El navegador suele mostrar ambos elementos con una diferencia visual, pero su finalidad principal es comunicar significado. No los uses únicamente para conseguir texto en negrita o cursiva; si solo necesitas presentación, esa decisión corresponde a CSS.

#### `<mark>`: contenido destacado

`<mark>` señala una parte relevante dentro de un contexto concreto, por ejemplo una coincidencia en una búsqueda:

```html
<p>Busca el concepto <mark>HTML semántico</mark> en esta página.</p>
```

No marques párrafos completos sin una razón. El elemento sirve para destacar una parte que tiene especial relevancia dentro del texto.

#### `<small>`: información secundaria

`<small>` representa texto secundario, como una aclaración, una nota legal o la fecha de actualización:

```html
<p>Última actualización: <small>septiembre de 2026</small></p>
```

No lo utilices solo para conseguir una letra pequeña. El tamaño visual se puede modificar con CSS, mientras que `<small>` comunica que el texto tiene menor relevancia dentro de su contexto.

#### `<span>`: agrupación de texto sin significado propio

`<span>` permite agrupar una parte de texto cuando se necesita identificarla o aplicarle estilos, pero no existe una etiqueta semántica más adecuada:

```html
<p>Estado: <span class="estado">en progreso</span></p>
```

A diferencia de `<p>`, `<span>` no crea un bloque de texto ni describe qué significa su contenido. Es un contenedor genérico en línea.

#### `<br>`: salto de línea intencional

`<br>` crea un salto de línea dentro del mismo contenido. Úsalo cuando el salto forma parte del significado, como en una dirección o un poema:

```html
<p>
  Calle del Aprendiz, 15<br>
  Madrid, España
</p>
```

No lo uses para separar párrafos o crear espacio entre elementos. En esos casos, usa párrafos o deja que CSS controle la separación.

Estas etiquetas son una primera aproximación al contenido textual. En la siguiente sesión se estudiarán con más detalle los párrafos, los saltos, las listas, los enlaces y la navegación.

### `<section>`

Agrupa contenido relacionado que forma una parte identificable de una página. Una sección normalmente necesita un encabezado propio:

```html
<section>
  <h2>Fundamentos</h2>
  <p>Conceptos iniciales de HTML.</p>
</section>
```

No uses `<section>` solo para crear un espacio visual o aplicar estilos. Si el grupo no tiene un tema reconocible, probablemente un `<div>` sea suficiente.

También puede asociarse una sección con su encabezado mediante `aria-labelledby` cuando el encabezado no puede ser una relación directa o cuando se necesita hacer explícita la relación:

```html
<section aria-labelledby="recursos-titulo">
  <h2 id="recursos-titulo">Recursos</h2>
  ...
</section>
```

### `<article>`

Representa contenido independiente y reutilizable. Si se extrae del resto de la página, debería conservar su sentido.

Ejemplos habituales son una noticia, una publicación de blog, una pregunta de un foro, una reseña o una tarjeta de producto completa.

```html
<section>
  <h2>Artículos recientes</h2>

  <article>
    <h3>Primeros pasos con HTML</h3>
    <p>Una introducción para comenzar a crear documentos web.</p>
  </article>

  <article>
    <h3>Cómo revisar una página</h3>
    <p>Una lista de comprobaciones para detectar errores comunes.</p>
  </article>
</section>
```

Una página puede contener varios `<article>` y un `<article>` puede contener secciones internas. La decisión depende de si el contenido es una unidad independiente, no de cuántos elementos visuales tenga.

### `<aside>`

Contiene información relacionada pero secundaria respecto al contenido principal. Puede ser una recomendación, una nota, un glosario breve o recursos relacionados.

```html
<aside>
  <h2>Para recordar</h2>
  <p>El HTML describe el contenido; CSS controla su presentación.</p>
</aside>
```

Si el contenido es necesario para comprender el tema principal, probablemente no sea un `<aside>`.

### `<footer>`

Representa información final de una página o de una sección. Puede contener datos de autoría, información relacionada, referencias o navegación secundaria.

Al igual que `<header>`, puede utilizarse dentro de un `<article>`:

```html
<article>
  <h2>HTML semántico</h2>
  <p>El contenido del artículo...</p>
  <footer>
    <p>Escrito por el equipo de documentación.</p>
  </footer>
</article>
```

## Elegir entre `section`, `article` y `div`

Estos elementos suelen confundirse. Puedes usar esta guía rápida:

| Elemento | Úsalo cuando... |
| --- | --- |
| `<article>` | el contenido puede entenderse o reutilizarse de forma independiente; |
| `<section>` | agrupas contenido relacionado bajo un tema y normalmente tienes un encabezado; |
| `<div>` | necesitas un contenedor sin significado semántico propio. |

Un `<article>` no es una “tarjeta visual” por definición. Una tarjeta de producto puede ser un `<article>` si representa un producto completo e independiente; si solo es un bloque utilizado para organizar el diseño, no necesariamente lo es.

## Jerarquía de encabezados

Los encabezados describen la organización del contenido. No los elijas por su tamaño visual, porque ese aspecto se controla con CSS.

```html
<h1>Guía de viajes</h1>

<h2>Destinos</h2>
<h3>Montaña</h3>
<h3>Playa</h3>

<h2>Consejos</h2>
```

Una página suele tener un encabezado principal `<h1>`. Después, usa `<h2>` para las secciones principales y `<h3>` para subsecciones de un `<h2>`. No saltes de `<h2>` a `<h4>` solo porque el tamaño predeterminado te parece adecuado.

La jerarquía debe representar la relación de las ideas. No conviertas todos los títulos en `<h1>` ni uses encabezados vacíos para generar espacio.

## Semántica y accesibilidad

El HTML semántico crea un mapa que puede ser interpretado de distintas formas:

- un navegador muestra el documento;
- un buscador identifica temas y relaciones;
- un lector de pantalla puede ofrecer una lista de regiones y encabezados;
- una persona que navega con teclado encuentra una estructura más predecible.

Esto no significa que las etiquetas semánticas resuelvan por sí solas la accesibilidad. El contenido debe tener una jerarquía lógica, los nombres deben ser comprensibles y los controles deben utilizar elementos adecuados.

### Prefiere HTML nativo antes que ARIA

ARIA puede aportar información adicional, pero no debería reemplazar un elemento HTML que ya expresa el significado:

```html
<!-- Preferible: el elemento ya tiene significado nativo -->
<button type="button">Mostrar detalles</button>

<!-- Menos recomendable: imita el significado con ARIA -->
<div role="button">Mostrar detalles</div>
```

El segundo ejemplo exigiría programar comportamientos adicionales para que funcionara correctamente con teclado y tecnologías de asistencia. En general, elige primero el elemento HTML que ya resuelve el problema.

## Un ejemplo completo

Este ejemplo reúne las decisiones principales de la sesión. Los enlaces se muestran solo para completar la estructura; su uso detallado corresponde a la siguiente sesión.

```html
<body>
  <header>
    <h1>Blog de aprendizaje web</h1>

    <nav aria-label="Navegación principal">
      <a href="/">Inicio</a>
      <a href="/temas">Temas</a>
    </nav>
  </header>

  <main>
    <section>
      <h2>Artículos recientes</h2>

      <article>
        <header>
          <h3>Cómo empezar con HTML</h3>
          <p>Una guía para crear el primer documento.</p>
        </header>

        <p>HTML permite organizar el contenido de una página web.</p>

        <footer>
          <p>Publicado por el equipo de aprendizaje.</p>
        </footer>
      </article>
    </section>

    <aside>
      <h2>Contenido relacionado</h2>
      <p>Consulta el glosario para repasar conceptos.</p>
    </aside>
  </main>

  <footer>
    <p>Material de aprendizaje colaborativo.</p>
  </footer>
</body>
```

Observa que:

1. `<main>` aparece una sola vez.
2. El `<article>` tiene sentido aunque se separe de la página.
3. `<section>` agrupa los artículos bajo un tema y tiene un encabezado.
4. `<aside>` aporta información relacionada, pero no es el contenido principal.
5. Los encabezados muestran la relación entre la página, la sección y el artículo.
6. Hay dos `<footer>` porque uno pertenece al artículo y otro a la página completa.

## Errores frecuentes

- Usar `<div>` para todo sin preguntarse si existe un elemento con significado.
- Usar `<section>` únicamente para aplicar estilos o crear espacios.
- Crear varios `<main>` en el mismo documento.
- Colocar todo el contenido dentro de `<header>` o `<footer>` porque son contenedores visuales.
- Utilizar `<article>` para cualquier tarjeta sin comprobar si es contenido independiente.
- Elegir encabezados por su tamaño en lugar de por su nivel dentro del contenido.
- Añadir `role` o atributos ARIA cuando el HTML nativo ya expresa la función.
- Usar `<nav>` para cualquier grupo pequeño de enlaces.
- Crear regiones semánticas sin encabezados claros ni contenido relacionado.
