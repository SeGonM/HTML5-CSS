# 2.1. Selectores y cascada

Los selectores son la puerta de entrada del CSS. Le dicen al navegador: “este estilo aplica a estos elementos concretos”. Sin selectores, el navegador no sabría qué reglas corresponde a cada parte del documento.

La cascada es el mecanismo que resuelve conflictos cuando varias reglas intentan afectar al mismo elemento. Elegir un selector adecuado y entender cómo se resuelve la prioridad te permite escribir CSS predecible, mantenible y fácil de depurar.

## 1. ¿Qué es un selector?

Un selector es una expresión que identifica uno o varios elementos del DOM. Por ejemplo:

```css
p {
  color: #1f2937;
}
```

Aquí el selector `p` coincide con todos los párrafos del documento. El navegador revisa el árbol de elementos y comprueba qué nodos cumplen la condición.

La parte importante no es solo “qué es el selector”, sino “qué conjunto de elementos coincide”. Un selector bien elegido tiene tres cualidades:

- precisión: apunta a los elementos correctos;
- reutilización: se puede aplicar consistentemente;
- mantenibilidad: es claro y fácil de modificar.

## 2. Selectores básicos

### Selector de tipo

```css
p { color: #333; }
h1 { font-size: 2rem; }
```

El selector de tipo coincide con todos los elementos de ese nombre HTML. Es simple pero poco específico.

### Selector de clase

```css
.aviso {
  background: #fff3cd;
  color: #664d03;
}
```

La clase se usa para agrupar elementos que comparten una intención conceptual o un estilo concreto. Por ejemplo, todos los mensajes de advertencia pueden tener la clase `.aviso`.

Es más reutilizable que un selector de tipo, porque puedes aplicar la misma clase a varios elementos distintos sin depender de su etiqueta HTML.

### Selector de ID

```css
#principal {
  max-inline-size: 70ch;
  margin-inline: auto;
}
```

El selector de ID se escribe con `#` seguido del nombre del identificador. El símbolo `#` le dice al navegador: “busca exactamente este elemento cuyo atributo `id` tenga ese valor”.

```html
<main id="principal">...</main>
```

Esto significa que el selector `#principal` coincide solo con ese `main` concreto.

#### ¿Cómo se selecciona un ID?

La sintaxis es muy directa:

```css
#mi-id {
  color: red;
}
```

Y el HTML debe tener:

```html
<div id="mi-id">Contenido</div>
```

El valor del `id` debe ser único dentro del documento. No puede haber dos elementos con el mismo `id` en la misma página, porque ese identificador debe ser único y sirve como referencia precisa.

#### Importante: `#` no significa “cualquier cosa”

```css
#menu {
  background: #111827;
}
```

Esto solo afecta al elemento cuyo `id` sea exactamente `menu`.

No vale esto:

```css
#menu .item { ... }
```

para seleccionar varios elementos. La parte `#menu` apunta a un único elemento, y la parte `.item` apunta a sus descendientes. Es una combinación de dos selectores, no “como si # fuera una clase”.

#### Diferencia entre `#id` y `.clase`

- `#principal` selecciona un único elemento con ese `id`.
- `.aviso` puede seleccionar muchos elementos que compartan la misma clase.

Por eso, un `id` es ideal para una identidad única, como:

- la cabecera principal;
- un contenedor principal de la página;
- un ancla de navegación interna;
- un bloque específico que debe identificarse con precisión.

Y una clase es ideal para:

- botones repetidos;
- tarjetas; 
- alertas;
- componentes reutilizables.

#### Cuándo usar IDs y cuándo no

```css
#header { ... }
#main { ... }
#contacto { ... }
```

Estos son buenos para elementos bien concretos, especialmente cuando necesitas enlazar a una sección con un ancla.

```html
<a href="#contacto">Ir a contacto</a>
<section id="contacto">...</section>
```

En cambio, esto no es recomendable:

```css
#boton, #boton2, #boton3 { ... }
```

porque estás repitiendo estilo en varios ID distintos. En ese caso, la clase es la opción más apropiada:

```css
.boton { ... }
```

#### Regla práctica

Usa ID para:

- un único elemento;
- navegación interna;
- identificadores semánticos únicos;
- elementos que realmente necesitan ser únicos.

Usa clase para:

- estilos reutilizables;
- múltiples elementos con la misma apariencia;
- componentes y patrones de diseño.

#### Selectores con ID combinados

Puedes combinar un ID con otros selectores cuando quieres ser más preciso:

```css
#principal p {
  color: #333;
}
```

Esto significa: “selecciona todos los `p` que estén dentro del elemento con `id="principal"`”.

Otro ejemplo:

```css
#menu > a {
  font-weight: 700;
}
```

Esto selecciona solo los enlaces directos dentro del menú.

#### Cuidado con el abuso de IDs

Aunque un ID es muy fuerte en CSS, no significa que debas usarlo como base para todo. El problema es que un selector con ID tiene mucha especificidad y puede complicar la cascada si se usa demasiado.

Por ejemplo:

```css
#app .card .button { ... }
```

Esto funciona, pero es más frágil y más difícil de mantener que algo como:

```css
.card__button { ... }
```

Por eso, en proyectos modernos, las clases suelen ser preferidas como base estructural del estilo.

### Selector universal

```css
* {
  box-sizing: border-box;
}
```

El selector universal coincide con todos los elementos. Se usa con cuidado; es muy amplio. En proyectos reales se suele combinar con `*::before` y `*::after` para normalizar el comportamiento de pseudo-elementos.

## 3. Combinadores

Los combinadores permiten describir relaciones entre elementos.

### Descendiente

```css
article p {
  line-height: 1.7;
}
```

Esto significa: “cualquier `p` que esté dentro de un `article`, sin importar cuán profundo esté”. Si hay un `p` dentro de un `section` dentro de un `article`, también coincide.

Este selector es muy útil pero también puede ser demasiado amplio si se aplica sin pensar.

### Hijo directo

```css
nav > a {
  text-decoration: none;
}
```

Este selector solo coincide con los elementos `a` que son hijos directos de `nav`.

No coincide con esto:

```html
<nav>
  <div>
    <a>Enlace</a>
  </div>
</nav>
```

porque el `a` no es hijo directo de `nav`.

### Hermano adyacente

```css
h2 + p {
  margin-top: 0.5rem;
}
```

Coincide con el `p` que aparece inmediatamente después de un `h2` como hermano cercano.

### Hermano general

```css
input ~ .ayuda {
  display: block;
}
```

Coincide con todos los elementos `.ayuda` que siguen a un `input` y comparten el mismo padre.

## 4. Selectores más avanzados

### Selector por atributo

```css
input[type="email"] { ... }
a[href^="https://"] { ... }
img[alt] { ... }
```

Sirven para seleccionar elementos según sus atributos.

Algunos ejemplos comunes:

```css
[href] { color: inherit; }
[href="/inicio"] { font-weight: 700; }
[disabled] { opacity: 0.6; cursor: not-allowed; }
```

También puedes usar comparadores:

```css
[href^="https://"] { /* empieza por */ }
[href$=".pdf"] { /* termina por */ }
[href*="example"] { /* contiene */ }
```

Estos selectores son muy útiles para formularios, enlaces y validación de contenido.

### Pseudo-clases

Las pseudo-clases añaden condiciones lógicas sin modificar el HTML:

```css
a:hover { color: #005fcc; }
button:focus-visible { outline: 2px solid #2563eb; }
input:checked + label { font-weight: 700; }
li:first-child { ... }
li:last-child { ... }
```

Ejemplos comunes:

- `:hover` para el hover del mouse;
- `:focus` y `:focus-visible` para accesibilidad y teclado;
- `:checked` para inputs seleccionados;
- `:nth-child()` para reglas de posición en listas o tablas;
- `:not()` para excluir elementos.

```css
.card:not(.featured) {
  opacity: 0.8;
}
```

### Pseudo-elementos

Los pseudo-elementos representan partes conceptuales del documento, no elementos reales del HTML.

```css
p::first-line { font-weight: 700; }
blockquote::before { content: "“"; }
```

Son muy útiles para estilos decorativos o para demostrar contenido textual sin cambiar el HTML.

## 5. Selector de lista

Puedes aplicar la misma regla a varios selectores a la vez:

```css
h1, h2, h3 {
  font-family: system-ui, sans-serif;
}
```

Esto facilita mantener una base de tipografía coherente.

## 6. La cascada: ¿qué pasa si dos reglas chocan?

La cascada no es un caos: es un algoritmo. El navegador evalúa varias reglas que pueden afectar al mismo elemento y decide cuál gana.

El orden de resolución se basa en varias capas:

1. origen de la hoja de estilos;
2. importancia (`!important`);
3. especificidad del selector;
4. orden de aparición.

Es decir, si dos declaraciones tienen igual origen, igual importancia y igual especificidad, gana la última que aparece en el archivo.

### Ejemplo básico

```css
p {
  color: navy;
}

p {
  color: teal;
}
```

Ambas reglas tienen el mismo origen, la misma importancia y la misma especificidad, así que gana la que aparece después.

## 7. Origen de las reglas

CSS tiene diferentes fuentes de estilo, y no todas tienen la misma prioridad.

### 1. Autor

Son las reglas escritas por el desarrollador en el proyecto.

```css
.card { background: white; }
```

Es la fuente más importante en la mayoría de los proyectos.

### 2. Usuario

Pueden venir desde preferencias del usuario o estilos personalizados del navegador.

### 3. Agente de usuario (navegador)

Los estilos por defecto del navegador, como `a { color: blue; }`, `h1 { font-size: 2em; }`.

La prioridad general es:

- navegador
- usuario
- autor

Y, además, dentro de cada nivel existe la diferencia entre estilos normales y con `!important`.

### Ejemplo de prioridad por origen

```css
body { color: black; }
```

```css
body { color: maroon !important; }
```

Aunque el autor escriba otra regla sin `!important`, la regla con `!important` gana en la misma fuente si el origen es el mismo.

## 8. Importancia: `!important`

`!important` eleva la prioridad de una declaración sobre otras declaracions del mismo origen.

```css
p {
  color: red;
}

p {
  color: blue !important;
}
```

La declaración azul gana aunque aparezca antes o después, siempre que sean del mismo origen.

Sin embargo, `!important` no debe usarse como solución habitual. Es una herramienta de excepción, no una estrategia de diseño. Cuando se usa demasiado, el CSS se vuelve difícil de depurar porque rompe la lógica de la cascada.

### Buenas prácticas

- usarlo solo en casos muy puntuales;
- preferir una estructura más clara de selectores y especificidad;
- evitarlo para “arreglar” conflicto general de estilos;
- si lo usas, documenta por qué es necesario.

## 9. Especificidad: qué tan concretamente apunta un selector

La especificidad mide cuán específico es un selector. Cuanto más específico, más peso tiene.

La idea general es:

- ID tiene mucha fuerza;
- clases, atributos y pseudo-clases tienen algo de fuerza;
- tipos y pseudo-elementos tienen menos fuerza.

### Regla simplificada

Se cuentan estos componentes:

- 1 por cada ID;
- 1 por cada clase, atributo o pseudo-clase;
- 1 por cada tipo o pseudo-elemento;

Entonces:

```css
p { ... }               /* 0-0-1 */
.card { ... }           /* 0-1-0 */
#principal p { ... }    /* 1-0-1 */
```

En la notación más común se expresa como `(a, b, c)`:

- `a` = número de ID;
- `b` = número de clases/atributos/pseudo-clases;
- `c` = número de tipos/pseudo-elementos.

Ejemplos:

```css
p                     /* (0,0,1) */
.card                 /* (0,1,0) */
#nav .link            /* (1,1,0) */
body .card p          /* (0,1,2) */
```

Cuando comparas dos selectores, se comparan de izquierda a derecha:

- primero el número de ID;
- luego clases;
- luego tipos.

Cuanto mayor sea el valor, más prioridad.

### Importante: no todo es “más específico = mejor”

Un selector más específico no siempre es la solución correcta. A veces una regla demasiado específica:

- es más difícil de reutilizar;
- aumenta el acoplamiento del CSS al HTML;
- empeora la legibilidad;
- hace que el mantenimiento sea más frágil.

La clave es equilibrar precisión y claridad.

## 10. Orden de aparición

Cuando dos declaraciones tienen el mismo origen, la misma importancia y la misma especificidad, gana la que aparece más tarde en el archivo.

```css
.button {
  background: blue;
}

.button {
  background: red;
}
```

El segundo color gana porque se escribió después.

Esto es útil, pero también puede provocar errores si el proyecto crece sin organización. Por eso la arquitectura del CSS importa tanto como la sintaxis.

## 11. Cómo se resuelve la cascada en la práctica

El navegador realiza esta evaluación conceptual:

1. recopila todas las reglas aplicables al elemento;
2. ordena por origen e importancia;
3. compara la especificidad;
4. si siguen empatadas, usa el orden de aparición.

Entonces el valor final es el ganador de ese proceso.

### Ejemplo completo

```css
p {
  color: black;
}

.article p {
  color: green;
}

.article .destacado {
  color: red;
}
```

```html
<article class="article">
  <p class="destacado">Texto</p>
</article>
```

El navegador aplica la regla más específica:

- `p` = (0,0,1)
- `.article p` = (0,1,1)
- `.article .destacado` = (0,2,0)

La última gana porque es más específica, aunque no sea la última en aparecer necesariamente.

## 12. Herencia y cascada son conceptos relacionados

La herencia es otra pieza importante del CSS. Algunas propiedades se heredan a los elementos hijos, como `color`, `font-family` y `line-height`.

```css
body {
  color: #222;
  font-family: system-ui, sans-serif;
}
```

Entonces, un `p` sin color definido usa el color del `body`.

Sin embargo, no todas las propiedades heredan:

```css
body {
  margin: 2rem;
}
```

No hace que todos los hijos hereden ese margen. El margen se usa en el elemento al que se aplica, no se transmite.

## 13. `inherit`, `initial`, `unset` y `revert`

Estas palabras clave permiten controlar el comportamiento de la herencia con precisión.

```css
button {
  font: inherit;
  color: inherit;
}
```

- `inherit`: hereda el valor del padre.
- `initial`: vuelve al valor inicial del navegador.
- `unset`: usa `inherit` si la propiedad es heredable; si no, usa `initial`.
- `revert`: revierte a la base del usuario o navegador, dependiendo del contexto.

Estas herramientas son muy útiles para evitar comportamientos raros y trabajar con componentes más consistentes.

## 14. Errores comunes al trabajar con selectores y cascada

### 1. Seleccionar por etiqueta cuando se quiere reutilizar

```css
div p { ... }
```

Esto es muy amplio y poco estable. Si el contenido cambia, el estilo puede romperse sin querer.

### 2. Usar IDs para estilos repetidos

```css
#boton { ... }
```

Si hay varios botones, un ID solo sirve a uno. Es más práctico usar una clase.

### 3. Confiar solo en el orden

```css
.card { color: red; }
.card { color: blue; }
```

Esto funciona, pero crea un CSS frágil y difícil de mantener. Mejor usar selectores más claros o capas de estilos bien organizadas.

### 4. Usar `!important` para arreglar todo

Cuando un proyecto crece, el abuso de `!important` se convierte en un problema mayor que el conflicto original. Es mejor entender la especificidad y reorganizar la estructura de estilos.

### 5. Confundir descendiente con hijo directo

```css
nav a { ... }
```

Esto incluye todos los enlaces dentro de `nav`, incluso si están anidados varios niveles.

```css
nav > a { ... }
```

Esto solo incluye los enlaces que son hijos directos.

## 15. Cómo escribir selectores más inteligentes

La clave no es “hacerlos más largos”, sino “hacerlos más expresivos”.

### Preferible

```css
.card__title { ... }
.alert--warning { ... }
```

### Menos recomendable

```css
div div .texto strong { ... }
```

Hay un principio práctico muy útil: “selector de clase + semántica + intención”. Si el selector expresa la intención del elemento, es más fácil mantenerlo.

## 16. Estrategia recomendable en proyectos reales

Cuando el proyecto crece, conviene pensar en capas:

- estilos base: reset, tipografía, variables, colores;
- estilos de componente: cards, botones, formularios;
- utilidades: clases de ayuda como `.text-center`, `.mt-4`;
- ajustes por estado: `.is-active`, `.is-error`, `.is-hidden`;
- reglas específicas por contexto.

Esto ayuda a evitar conflictos caóticos entre reglas globales y reglas locales.

## 17. Resumen mental

Si quieres recordar la lógica de la cascada, piensa en esto:

- selector decide a qué elementos aplica;
- origen decide de dónde viene la regla;
- `!important` sube su prioridad;
- especificidad decide cuán concreta es la regla;
- orden decide entre reglas equivalentes.

En otras palabras:

> CSS no “adivina”; aplica un algoritmo claro para decidir cuál es el valor final.

## 18. En conclusión

Los selectores y la cascada son las bases que permiten que CSS no sea un lenguaje caótico, sino un sistema ordenado de reglas. Dominar este tema te ayuda a:

- aplicar estilos correctamente;
- evitar conflictos invisibles;
- escribir CSS más claro y mantenible;
- entender por qué el navegador elige un valor y no otro.

Es uno de los conceptos más importantes del desarrollo front-end, porque gobierna casi toda la lógica visual de la página.
