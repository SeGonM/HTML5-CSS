# 3.5. Overflow y contención

El **desbordamiento** (*overflow*) ocurre cuando el contenido de una caja es más grande que el espacio disponible dentro de ella. Imagina una caja de zapatos: si intentas meter algo demasiado grande, debes decidir si lo dejas salir, lo cortas o haces la caja accesible para poder mirar su interior por partes.

En CSS, esa “caja” tiene contenido, `padding`, borde y margen, como se explicó en [2.3. Modelo de caja](../Modelo-en-caja/2.3-modelo-de-caja.md). El contenido puede crecer por varias razones:

- un párrafo tiene muchas palabras;
- una imagen es más ancha que su contenedor;
- una tabla necesita más columnas de las que caben;
- una lista tiene más filas que la altura disponible;
- un elemento `absolute` se coloca fuera de los límites de su padre.

`overflow` no cambia el tamaño del contenido ni lo hace desaparecer mágicamente: define qué parte se muestra y si existe una forma de desplazarse. Esto es diferente de `display: none`, que no genera una caja, y de `position`, que decide cómo se coloca una caja, temas tratados anteriormente en [3.2. `display`](3.2-display.md) y [3.3. `position`](3.3-position.md).

## 1. El ejemplo base: una caja pequeña con mucho contenido

```html
<section class="noticias">
  <h2>Noticias</h2>
  <p>Primera noticia...</p>
  <p>Segunda noticia...</p>
  <p>Tercera noticia...</p>
  <p>Cuarta noticia...</p>
</section>
```

```css
.noticias {
  max-block-size: 12rem;
  padding: 1rem;
  border: 1px solid #94a3b8;
}
```

`max-block-size` limita el tamaño de la caja en el eje de bloque. Las unidades `rem` y las dimensiones relativas se explican en [2.4. Unidades CSS modernas](../Modelo-en-caja/2.4-unidades-css-modernas.md). Como el contenido puede superar esos `12rem`, ahora necesitamos decidir qué hacer con lo que sobra.

## Valores de `overflow`

```css
.panel {
  overflow: auto;
}
```

| Valor | Comportamiento |
|---|---|
| `visible` | El contenido puede dibujarse fuera de la caja. Es el valor inicial habitual. |
| `hidden` | Recorta el contenido que sale de la caja y permite desplazamiento programático, pero no muestra barras para desplazarlo manualmente. |
| `clip` | Recorta el contenido sin crear un contenedor de desplazamiento. |
| `scroll` | Crea un mecanismo de desplazamiento, aunque no siempre se vean las barras según el sistema operativo. |
| `auto` | Permite desplazamiento cuando el contenido lo necesita. |

La diferencia práctica es esta:

- **`visible`**: prioriza mostrar todo, aunque sobresalga;
- **`hidden`**: prioriza mantener un rectángulo limpio y corta lo que sobra;
- **`scroll`**: reserva un mecanismo de desplazamiento aunque quizá no haga falta;
- **`auto`**: crea desplazamiento solo cuando el contenido realmente no cabe;
- **`clip`**: corta sin convertir la caja en un área desplazable.

### `visible`: dejar que el contenido salga

Es el valor inicial habitual. Si una imagen, sombra o elemento es más grande que su caja, puede dibujarse fuera de ella.

```css
.marco {
  inline-size: 12rem;
  border: 2px solid #334155;
  overflow: visible;
}
```

Es útil cuando no quieres cortar sombras, adornos o un menú que debe aparecer fuera de su botón. No es buena elección para una tabla o una lista que debe mantenerse dentro de un panel, porque el contenido puede tapar otros elementos.

### `hidden`: cortar sin mostrar barras

```css
.avatar {
  inline-size: 4rem;
  block-size: 4rem;
  border-radius: 50%;
  overflow: hidden;
}
```

Aquí una imagen grande puede quedar recortada dentro del círculo. Este patrón funciona para imágenes decorativas, tarjetas y animaciones en las que una parte debe quedar fuera de la caja.

Pero `hidden` también puede ocultar contenido importante. Una persona no podrá descubrir con la rueda del ratón o con el dedo la parte que cortaste. Además, un descendiente con `position: absolute` puede quedar cortado, aunque tenga un `z-index` alto; como se explicó en [3.4. Contexto de apilamiento](3.4-contexto-de-apilamiento.md), el orden de pintura no permite escapar de un límite de recorte.

### `scroll`: ofrecer desplazamiento siempre

```css
.historial {
  max-block-size: 16rem;
  overflow: scroll;
}
```

El contenido puede recorrerse, pero el navegador reserva un mecanismo de desplazamiento incluso cuando todo cabe. Esto puede provocar barras innecesarias o consumir espacio visual. Úsalo cuando quieres comunicar claramente que el área es desplazable o necesitas un tamaño estable entre estados.

### `auto`: desplazamiento solo cuando hace falta

```css
.mensajes {
  max-block-size: 20rem;
  overflow: auto;
}
```

Si los mensajes caben, no aparece una barra. Si crecen demasiado, el panel se convierte en un área desplazable. Es la opción más habitual para listas, historiales y paneles de contenido variable.

Para que `auto` tenga un efecto visible debe existir un límite de tamaño. Si la caja puede crecer sin límite, crecerá con el contenido y nunca tendrá nada que desplazar:

```css
/* No limita el tamaño: probablemente no habrá desplazamiento. */
.lista-sin-limite {
  overflow: auto;
}

/* Sí limita el alto disponible. */
.lista-limitada {
  max-block-size: 18rem;
  overflow: auto;
}
```

### `clip`: cortar sin crear un área desplazable

```css
.decoracion {
  overflow: clip;
}
```

`clip` es más explícito que `hidden` cuando solo quieres impedir que la pintura salga y no quieres que esa caja se comporte como un contenedor de desplazamiento. No lo uses para ocultar texto esencial: el contenido seguirá sin estar disponible visualmente.

Para que una caja se convierta en un área con desplazamiento, normalmente necesita una dimensión limitada en el eje correspondiente:

```css
.lista {
  max-block-size: 18rem;
  overflow-y: auto;
}
```

El contenido adicional se puede recorrer sin hacer crecer indefinidamente el componente.

## 2. Elegir el eje correcto

## Ejes horizontal y vertical

Se pueden controlar los ejes por separado con `overflow-x` y `overflow-y`, o usar propiedades lógicas como `overflow-inline` y `overflow-block`.

```css
.tabla-contenida {
  overflow-x: auto;
}
```

Esto puede ser útil para una tabla ancha. Evita añadir desplazamiento horizontal a toda la página cuando basta con contenerlo alrededor del componente.

Combinar valores distintos en cada eje puede tener interacciones definidas por CSS: ciertos valores pueden computarse como `auto` o `hidden` cuando el otro eje crea un contenedor de desplazamiento. Si el resultado sorprende, inspecciona los valores computados en las herramientas de desarrollo.

### Ejemplo: tabla ancha en una pantalla pequeña

Una tabla puede necesitar más espacio horizontal del que tiene un teléfono. En lugar de hacer que toda la página se desplace lateralmente, envuelve la tabla en un contenedor:

```html
<div class="tabla-contenida">
  <table>
    <tr>
      <th>Producto</th>
      <th>Enero</th>
      <th>Febrero</th>
      <th>Marzo</th>
    </tr>
  </table>
</div>
```

```css
.tabla-contenida {
  max-inline-size: 100%;
  overflow-x: auto;
}

table {
  min-inline-size: 40rem;
}
```

El contenedor conserva el ancho de la página y la tabla puede recorrerse horizontalmente dentro de él. `max-inline-size: 100%` evita que el envoltorio sea más ancho que su contenedor; `min-inline-size` expresa que la tabla necesita un mínimo para conservar su legibilidad.

## Truncar texto con `text-overflow`

`text-overflow` controla cómo se indica que una línea de texto se recortó, pero no recorta por sí misma el contenido. Es decir, escribir solo `text-overflow: ellipsis` no produce puntos suspensivos.

Para conseguir una elipsis en una sola línea se necesitan tres decisiones:

1. impedir que el texto salte a otra línea;
2. recortar lo que no cabe;
3. indicar el recorte con `text-overflow`.

```css
.nombre-archivo {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

La caja necesita un ancho o una restricción equivalente para que el texto no se expanda sin límite.

```html
<p class="nombre-archivo">
  informe-final-de-ventas-septiembre-2026.xlsx
</p>
```

En una interfaz real, la elipsis indica que falta información. Ofrece una forma de consultar el nombre completo, por ejemplo un atributo `title`, un detalle expandible o una vista accesible. No confíes solo en pasar el ratón: en pantallas táctiles y con teclado puede no existir ese gesto.

Para varias líneas, se puede considerar `line-clamp` donde sea apropiado y compatible con los navegadores objetivo:

```css
.resumen {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
  overflow: hidden;
}
```

No trunques contenido esencial sin ofrecer una forma de consultarlo completo. Comprueba también cómo se comporta con texto ampliado, traducciones y tecnologías de asistencia.

La elipsis de varias líneas es una decisión visual, no una eliminación real del texto. Si el resumen es necesario para entender una noticia, muestra el texto completo en la página de detalle o proporciona un control para expandirlo.

## Desplazamiento y experiencia de uso

`overflow: auto` puede crear un área que se desplaza de manera independiente a la página. En interfaces táctiles, `overscroll-behavior` permite controlar si el desplazamiento se propaga a los contenedores superiores:

```css
.panel-desplazable {
  max-block-size: 20rem;
  overflow: auto;
  overscroll-behavior: contain;
}
```

Usa esta propiedad con cuidado: impedir toda propagación puede hacer que la navegación por desplazamiento se sienta atrapada.

### Cómo se desplaza una persona

Una persona puede recorrer un área con `overflow` usando la rueda del ratón, un gesto táctil, las teclas de dirección, `Page Up`, `Page Down`, `Home` y `End`, o un lector de pantalla. Por eso un área desplazable debe ser reconocible y tener suficiente tamaño para interactuar con ella.

```css
.panel-desplazable {
  max-block-size: 20rem;
  overflow-y: auto;
  padding: 1rem;
  scroll-behavior: smooth;
}
```

`scroll-behavior: smooth` anima los desplazamientos iniciados por código o navegación interna. No lo conviertas en una condición para poder usar el contenido: algunas personas prefieren reducir el movimiento. Puedes respetar esa preferencia:

```css
@media (prefers-reduced-motion: reduce) {
  .panel-desplazable {
    scroll-behavior: auto;
  }
}
```

### Desplazamiento anidado

Si una página completa y un panel interior se desplazan, puede ocurrir que el gesto pase del panel a la página cuando el panel llega a su extremo. `overscroll-behavior: contain` evita esa propagación en el límite:

```css
.chat {
  max-block-size: 24rem;
  overflow-y: auto;
  overscroll-behavior: contain;
}
```

Esto puede ser útil en un chat o en una lista lateral, pero úsalo con criterio: si bloqueas demasiados niveles, la persona puede sentir que la interfaz dejó de responder.

### `sticky` y contenedores de desplazamiento

Un ancestro con `overflow: auto`, `scroll` o `hidden` puede convertirse en la referencia de un elemento `position: sticky`, como se explicó en [3.3. `position`](3.3-position.md). Por eso añadir `overflow: hidden` para recortar una decoración puede cambiar inesperadamente el comportamiento de un encabezado pegajoso. Antes de aplicar `overflow`, decide si ese elemento debe ser también un contenedor de desplazamiento.

## Contener trabajo de layout y pintura

La propiedad `contain` permite declarar que ciertas operaciones de layout, estilo, pintura o tamaño de un elemento están contenidas. En palabras sencillas, le dice al navegador: “esta zona es relativamente independiente; no necesitas recalcular o pintar fuera de ella por cada cambio interno”.

`contain` no es lo mismo que `overflow`:

- `overflow` decide qué ocurre con el contenido que sale de una caja;
- `contain` limita qué relaciones puede tener esa caja con el resto del layout, el tamaño, el estilo o la pintura.

Puede mejorar el rendimiento de widgets independientes, pero también puede cambiar el tamaño esperado, recortar sombras o alterar la referencia de elementos posicionados. Por eso no se añade automáticamente a todos los componentes.

```css
.widget-independiente {
  contain: layout paint;
}
```

En este caso:

- `layout` trata el layout interno del widget como una zona separada;
- `paint` impide que la pintura interna salga de sus límites;
- una sombra o un tooltip interno puede quedar recortado por `paint`;
- el cambio puede influir en el apilamiento y en el bloque contenedor de elementos posicionados.

### Ejemplo: una tarjeta independiente

```css
.grafico {
  inline-size: min(100%, 42rem);
  block-size: 20rem;
  padding: 1rem;
  border: 1px solid #cbd5e1;
  contain: layout paint;
}
```

Esto puede ser razonable para un gráfico que tiene límites claros y no necesita dibujar fuera de su tarjeta. No sería razonable si el mismo componente contiene un menú que debe salir por encima del borde o una sombra que debe extenderse fuera: en ese caso `paint` puede cortar justamente la parte que querías mostrar.

### `contain: size`

`contain: size` indica que el tamaño del elemento debe calcularse sin depender del contenido interno de la misma manera. Es útil en componentes con dimensiones explícitas, pero peligroso si esperas que la caja crezca automáticamente con su contenido.

```css
.marco-fijo {
  inline-size: 20rem;
  block-size: 12rem;
  contain: size;
}
```

Si el contenido crece, `contain: size` no debe utilizarse como sustituto de `overflow: auto`; son decisiones distintas. Una propiedad controla el cálculo del tamaño y la otra controla cómo se muestra el exceso.

Añade contención solo cuando el comportamiento deseado esté claro y se haya comprobado el resultado en contenido largo, zoom, móvil y tecnologías de asistencia.

## 6. Cómo elegir una solución

Antes de escribir `overflow`, responde estas preguntas:

1. ¿El contenido es importante o es solo decoración?
2. ¿Debe verse completo, recortarse o poder recorrerse?
3. ¿El exceso es horizontal, vertical o en ambos ejes?
4. ¿La caja tiene una altura o anchura limitada?
5. ¿Hay elementos `absolute`, `sticky` o sombras que necesiten salir de ella?
6. ¿La persona podrá usar el desplazamiento con ratón, teclado, táctil y zoom?

Una guía rápida:

| Necesidad | Solución habitual |
|---|---|
| Mostrar adornos fuera de la caja | `overflow: visible` |
| Recortar una imagen o decoración | `overflow: hidden` |
| Desplazarse solo cuando el contenido crece | `overflow: auto` |
| Mantener barras siempre disponibles | `overflow: scroll` |
| Recortar sin crear desplazamiento | `overflow: clip` |
| Mostrar puntos suspensivos en una línea | `overflow: hidden` + `white-space: nowrap` + `text-overflow` |
| Aislar un widget independiente | `contain`, después de comprobar sus efectos |

## 7. Diagnóstico de problemas comunes

### “`overflow: auto` no muestra barras”

Comprueba que exista una restricción de tamaño (`height`, `max-height`, `block-size`, `max-block-size`, etc.) y que el contenido realmente la supere. Si la caja crece con el contenido, no hay nada que desplazar.

### “La sombra o el tooltip desapareció”

Busca `overflow: hidden`, `overflow: clip` o `contain: paint` en un ancestro. El recorte puede estar funcionando correctamente, pero quizá se aplicó en una caja que debía permitir pintura externa.

### “La tabla rompe toda la página”

No escondas la tabla con `hidden`. Crea un envoltorio con `overflow-x: auto` para que la tabla se desplace dentro de una zona controlada.

### “La elipsis no aparece”

Revisa las tres condiciones: una sola línea (`white-space: nowrap`), recorte (`overflow: hidden`) y señal de recorte (`text-overflow: ellipsis`). También debe existir una anchura limitada.

### “`sticky` dejó de funcionar”

Inspecciona los ancestros. Un nuevo contenedor de desplazamiento creado por `overflow` puede haber cambiado los límites donde `sticky` intenta adherirse.

### “El texto queda cortado y no se puede leer”

Elige `auto` en vez de `hidden` si el texto es importante, o proporciona un control para expandirlo. Comprueba también el zoom, las traducciones y el tamaño de fuente aumentado.

## En resumen

- `overflow` define qué ocurre cuando el contenido excede una caja.
- `visible`, `hidden`, `scroll`, `auto` y `clip` expresan decisiones diferentes sobre mostrar, cortar o desplazar contenido.
- `auto` es una opción habitual para áreas que pueden necesitar desplazamiento, pero necesita una dimensión limitada.
- `text-overflow: ellipsis` requiere una caja limitada, una sola línea y `overflow: hidden`.
- `overflow` puede cambiar los límites de `sticky`, el recorte de elementos posicionados y la interacción táctil.
- Diseña las áreas desplazables y el texto truncado teniendo en cuenta accesibilidad, teclado, zoom y uso táctil.
- `contain` afecta al cálculo, al tamaño o a la pintura; no es sinónimo de `overflow`.
