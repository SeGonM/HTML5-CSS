# 3.4. Contexto de apilamiento

Cuando varias cajas ocupan una misma zona, el navegador necesita decidir cuál se pinta delante. Este problema aparece con menús, tooltips, tarjetas superpuestas, encabezados `sticky`, diálogos y elementos `fixed`.

Para entenderlo hay que separar tres ideas:

1. **posición**: dónde se coloca una caja y si conserva su espacio en el flujo, como se explicó en [3.3. `position`](3.3-position.md);
2. **orden de apilamiento**: en qué orden se pintan las cajas que pueden superponerse;
3. **contexto de apilamiento**: el grupo aislado dentro del que se compara ese orden.

`z-index` participa en la segunda idea, pero no elimina la tercera. Por eso “poner un `z-index` enorme” no resuelve todos los problemas de superposición.

## 1. `z-index`: un nivel, no una coordenada

`z-index` indica el nivel de una caja dentro del contexto de apilamiento al que pertenece. A igualdad de las demás condiciones, un nivel mayor se pinta delante de uno menor.

```css
.panel {
  position: relative;
  z-index: 1;
}

.menu {
  position: relative;
  z-index: 2;
}
```

Si `.panel` y `.menu` son comparables dentro del mismo contexto, `.menu` aparece delante donde sus áreas se superponen. El valor puede ser positivo, cero, negativo o `auto`:

- los valores positivos colocan el elemento en niveles superiores;
- `0` lo coloca en un nivel explícito cercano al nivel neutro;
- los valores negativos lo colocan por debajo de otros niveles del contexto, aunque siguen sujetos al fondo y a las reglas de su contexto;
- `auto` no crea por sí mismo un nuevo contexto para la mayoría de los elementos posicionados y deja que intervenga el orden de apilamiento correspondiente.

`z-index` acepta enteros, no solo números “típicos” como `10` o `9999`. La diferencia entre `2` y `2000` no importa si ambos se comparan con niveles de otro contexto: el navegador no trata el valor como una coordenada global.

### ¿Cuándo tiene efecto?

En el caso más habitual, `z-index` tiene efecto en un elemento cuyo `position` no sea `static`, por ejemplo `relative`, `absolute`, `fixed` o `sticky`. Esto enlaza directamente con [3.3. `position`](3.3-position.md).

También puede ordenar un **elemento flex** o un **elemento grid** aunque su `position` sea `static`, siempre que el `z-index` sea distinto de `auto`. Recuerda la distinción de [3.2. `display`](3.2-display.md): son los hijos directos de un contenedor flex o grid los que reciben ese tratamiento; los nietos no se vuelven comparables automáticamente.

```css
.fila {
  display: flex;
}

.fila .uno {
  z-index: 2;
}

.fila .dos {
  z-index: 1;
}
```

Si un elemento sigue siendo `position: static` y no es un flex item ni un grid item, asignarle `z-index` normalmente no basta para cambiar su orden.

## 2. ¿Qué es un contexto de apilamiento?

Un contexto de apilamiento es un grupo independiente de cajas que el navegador ordena como una unidad frente a otros grupos. Sus descendientes pueden competir entre sí, pero no compiten directamente con los descendientes de otro contexto.

Imagina dos niveles de comparación:

```text
Contexto raíz
├── contexto A: nivel 1
│   └── hijo: nivel 9999
└── contexto B: nivel 2
    └── hijo: nivel 0
```

Aunque el hijo de A tenga `9999`, todo el contexto A está por debajo de B porque A tiene nivel `1` y B nivel `2`. El hijo de A no puede escapar de su grupo para superar a B.

```css
.contenedor-a {
  position: relative;
  z-index: 1;
}

.contenedor-a .hijo {
  position: absolute;
  z-index: 9999;
}

.contenedor-b {
  position: relative;
  z-index: 2;
}
```

Este es el error conceptual más común: comparar el `z-index` del hijo de A con el `z-index` del hijo de B. La comparación correcta es primero entre A y B; solo después se compara a los hijos dentro de su propio contexto.

## 3. El contexto raíz y los contextos anidados

La página tiene un contexto de apilamiento raíz asociado al elemento raíz del documento. Dentro de él pueden aparecer nuevos contextos anidados. Cada contexto tiene su propio orden interno y se comporta como una sola pieza cuando se compara con sus hermanos.

Un contexto anidado no es lo mismo que cualquier elemento padre. Muchos padres contienen hijos sin crear una frontera de apilamiento. La frontera aparece cuando se cumple alguna condición específica de CSS. Por eso, al depurar, no basta con mirar el HTML: hay que revisar los estilos computados de cada ancestro.

La relación puede resumirse así:

```text
contexto exterior
├── caja normal
├── contexto interno A
│   ├── fondo de A
│   └── hijos ordenados dentro de A
└── contexto interno B
```

Los hijos de A nunca se comparan directamente con los hijos de B. Se compara A con B y, una vez elegido el contexto que queda delante, se utiliza el orden interno de ese contexto.

## 4. Cómo se crean nuevos contextos

Las causas más frecuentes son las siguientes:

- el elemento raíz del documento;
- `position: relative` o `position: absolute` junto con `z-index` distinto de `auto`;
- `position: fixed` o `position: sticky`;
- un flex item o grid item con `z-index` distinto de `auto`;
- `opacity` menor que `1`;
- `transform` distinto de `none`;
- `filter` o `backdrop-filter` distintos de `none`;
- `perspective` distinta de `none`;
- `mix-blend-mode` distinto de `normal`;
- `isolation: isolate`;
- ciertas formas de `contain`, especialmente `contain: paint`;
- propiedades de máscara, clip y composición que establecen aislamiento de pintura.

No todas estas propiedades se añaden para ordenar elementos. Por ejemplo, `transform` puede usarse para una animación y `opacity` para una transición, pero ambas también pueden crear una frontera de apilamiento. El efecto secundario es importante cuando dentro de ese elemento hay un menú, un tooltip o una caja que debería aparecer sobre otro componente.

### `position` y creación de contextos

`position: relative` por sí solo no siempre crea un contexto de apilamiento; normalmente lo crea cuando se combina con un `z-index` distinto de `auto`. En cambio, `fixed` y `sticky` se consideran contextos de apilamiento en las condiciones definidas por CSS, incluso cuando no se les asigna un número grande.

```css
.tarjeta {
  position: relative;
  /* No hay z-index: la caja puede no crear un contexto nuevo. */
}

.tarjeta-aislada {
  position: relative;
  z-index: 0;
  /* Ahora sí se establece una frontera de apilamiento. */
}
```

La diferencia entre estar posicionado y crear un contexto es importante: una caja puede responder a insets sin formar necesariamente una frontera independiente.

### `opacity` y transformaciones

Una opacidad menor que `1` crea un contexto porque el navegador debe componer el elemento y todo su contenido como una unidad antes de mostrarlo. Esto impide que un descendiente parcialmente transparente se mezcle libremente con elementos externos.

```css
.panel-transparente {
  opacity: 0.95;
}
```

De forma parecida, `transform: translate(...)` puede crear un contexto aunque la transformación visual parezca pequeña. Al quitar temporalmente `transform` durante una depuración, un problema de capas puede desaparecer y revelar su causa.

## 5. Stacking order: el orden de pintura

El **stacking order** es el orden en que se pintan las categorías de cajas dentro de un contexto. La especificación completa tiene más casos, pero este modelo práctico ayuda a razonar:

1. se pinta el fondo y el borde del elemento que establece el contexto;
2. se consideran los descendientes con niveles negativos, desde los más bajos hacia los más altos;
3. se pintan las cajas no posicionadas que participan en el flujo normal, siguiendo el orden del documento;
4. se pintan los elementos en línea y otros contenidos del flujo según su composición;
5. se consideran los elementos posicionados con `z-index: auto` o nivel neutro;
6. se pintan los contextos y elementos con niveles positivos, desde los más bajos hacia los más altos;
7. si dos elementos quedan en el mismo nivel, el que aparece después en el orden del documento suele quedar delante.

Este esquema es deliberadamente simplificado: flexbox, grid, elementos reemplazados, flotantes y otros detalles tienen reglas específicas. Aun así, evita el error de pensar que solo existe una lista de números.

### El orden del documento como desempate

Cuando dos cajas están en el mismo contexto y nivel, el orden del HTML puede decidir cuál se pinta después. En este ejemplo ambas cajas tienen el mismo `z-index`:

```css
.primera,
.segunda {
  position: relative;
  z-index: 1;
}
```

```html
<div class="primera">Primera</div>
<div class="segunda">Segunda</div>
```

Si se superponen, `.segunda` suele quedar delante porque aparece después. Cambiar el orden visual con posicionamiento no debería contradecir el orden semántico del HTML, una consideración relacionada con el flujo normal explicado en [3.1. Flujo normal](3.1-flujo-normal.md).

## 6. `z-index` negativo: útil, pero delicado

Un nivel negativo puede colocar una decoración detrás del contenido del mismo contexto:

```css
.tarjeta {
  position: relative;
  isolation: isolate;
}

.tarjeta::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  background: #dbeafe;
}
```

`isolation: isolate` hace que la tarjeta sea un contexto independiente y evita que la decoración negativa termine detrás de un fondo externo de forma inesperada. Sin aislamiento, un nivel negativo puede quedar detrás del fondo de un ancestro y parecer que desapareció.

No uses valores negativos para corregir cualquier problema de visibilidad. Primero determina qué contexto se está creando y qué fondo está cubriendo la caja.

## 7. Contexto de apilamiento no es lo mismo que recorte

`z-index` decide el orden de pintura, pero no permite escapar de un recorte. Si un ancestro limita la pintura o el desbordamiento, aumentar el nivel no hace visible la parte recortada.

Antes de cambiar el orden de apilamiento, distingue qué parte de la caja estás modificando. El contenido, el `padding`, el borde y el `margin` no significan lo mismo, como se explica en [2.3. Modelo de caja](../Modelo-en-caja/2.3-modelo-de-caja.md):

- usa `padding` para separar el contenido del borde de **la misma caja**;
- usa `border` para hacer visible o delimitar esa caja;
- usa `margin` para separar **una caja de sus vecinas**;
- usa `z-index` para decidir qué caja se pinta delante cuando sus áreas se superponen.

### Ejemplo: tarjeta, contenido y tooltip

```html
<article class="tarjeta">
  <h2>Curso de CSS</h2>
  <p>Contenido de la tarjeta.</p>
  <span class="ayuda">Más información</span>
</article>
```

```css
.tarjeta {
  position: relative;
  inline-size: 18rem;
  padding: 1rem;
  border: 1px solid #94a3b8;
  margin-block: 1rem;
  box-sizing: border-box;
}

.tarjeta h2 {
  margin-block-start: 0;
}

.ayuda {
  position: absolute;
  inset-block-start: 100%;
  inset-inline-start: 0;
  z-index: 10;
  padding: 0.5rem;
  border: 1px solid #475569;
  background: white;
}
```

Aquí `padding: 1rem` evita que el título y el párrafo queden pegados al borde de `.tarjeta`. Si usáramos `margin` en el artículo esperando conseguir ese espacio interior, el margen aparecería fuera de la tarjeta y no protegería su contenido.

El `margin-block: 1rem` sí tiene sentido en `.tarjeta` porque separa esta tarjeta de otros elementos vecinos. No cambia la posición del tooltip dentro de la tarjeta ni crea una capa nueva.

El `border` hace visible el límite de la tarjeta. Con `box-sizing: border-box`, el `inline-size: 18rem` incluye el contenido, el `padding` y el borde; sin esa decisión, el tamaño exterior sería mayor que los `18rem` declarados. Esto importa al calcular dónde empieza `inset-inline-start: 0` y qué zona puede ocupar el tooltip.

El tooltip usa `position: absolute` porque debe colocarse respecto a la tarjeta y no empujar el contenido. Usa `z-index: 10` porque puede superponerse a elementos cercanos. Si solo necesitáramos separar dos tarjetas, no usaríamos `z-index`: usaríamos `margin` o `gap` en su contenedor.

```css
.contenedor {
  overflow: hidden;
}

.tooltip {
  position: absolute;
  z-index: 9999;
}
```

El tooltip puede estar por delante de otros descendientes del contexto y aun así desaparecer fuera de `.contenedor`. En ese caso el problema no es el nivel, sino el límite de pintura o de desbordamiento. Esta distinción debe analizarse junto con las dimensiones y el layout explicados en [3.2. `display`](3.2-display.md).

## 8. Una escala de capas mantenible

Una escala pequeña expresa la intención mejor que números arbitrariamente grandes:

```css
:root {
  --layer-content: 0;
  --layer-decoration: 1;
  --layer-dropdown: 10;
  --layer-sticky: 20;
  --layer-dialog: 30;
}

.dropdown {
  position: absolute;
  z-index: var(--layer-dropdown);
}
```

Estas variables solo organizan los niveles dentro de un mismo contexto. No hacen que un dropdown dentro de un contexto inferior supere a un diálogo que pertenece a otro contexto superior. Si la escala parece no funcionar, la primera pregunta debe ser “¿están en el mismo contexto?”, no “¿necesito usar `999999`?”.

## 9. Depuración visual paso a paso

Cuando una caja aparece detrás de otra, sigue este orden:

### Paso 1: confirma que realmente hay superposición

Activa temporalmente un fondo translúcido y un borde en las cajas relevantes. Revisa sus dimensiones, `margin`, `padding` e insets. Un elemento puede parecer oculto cuando en realidad está desplazado, tiene tamaño cero o queda fuera de su bloque contenedor, conceptos que pertenecen al posicionamiento de [3.3. `position`](3.3-position.md).

```css
* {
  outline: 1px solid rgb(220 38 38 / 0.2);
}
```

Usa esta regla solo durante la inspección, porque también afecta a elementos internos.

### Paso 2: inspecciona el elemento y sus estilos computados

Revisa:

- `position`;
- `z-index` computado;
- `opacity`;
- `transform`, `filter` y `perspective`;
- `isolation` y `contain`;
- `overflow` de los ancestros;
- dimensiones, insets y márgenes.

No te quedes solo con la regla escrita en la hoja de estilos: otra regla puede haber ganado por cascada o especificidad.

### Paso 3: sube por la cadena de ancestros

Inspecciona cada padre hasta el elemento raíz. Marca mentalmente dónde aparece una frontera de apilamiento. El primer ancestro con `opacity`, `transform`, `isolation`, `contain` o un `z-index` aplicable puede explicar por qué el hijo no supera a un elemento externo.

### Paso 4: compara contextos antes que números

Si dos cajas están en contextos distintos, compara el nivel de sus contextos padres. Si están en el mismo contexto, compara sus niveles internos y finalmente el orden del documento.

```text
Incorrecto: 9999 del hijo A frente a 2 del hijo B
Correcto:   nivel del contexto A frente al contexto B
             y después los hijos dentro de su contexto
```

### Paso 5: descarta el recorte

Si el elemento tiene un nivel correcto pero una parte desaparece en el borde de un contenedor, revisa `overflow`, `clip-path`, máscaras y contención de pintura. Ningún `z-index` puede pintar fuera de un límite que recorta la caja.

### Paso 6: prueba la causa mínima

En las herramientas de desarrollo, desactiva temporalmente una propiedad cada vez: primero `z-index`, después `transform`/`opacity`, y luego el recorte del ancestro. Cambiar una sola variable permite saber qué propiedad controla el resultado, en lugar de acumular números y reglas contradictorias.

## 10. Errores frecuentes

### “Puse `z-index: 9999` y sigue detrás”

Probablemente el elemento está dentro de un contexto cuyo nivel completo queda por debajo de otro. Compara los ancestros y no solo el valor del descendiente.

### “`z-index` no funciona”

Comprueba si el elemento es `static` y no es un flex item ni un grid item. En caso contrario, `z-index` puede no participar como esperas.

### “El menú queda debajo después de añadir `transform`”

El `transform` del ancestro pudo crear un contexto nuevo. El menú sigue ordenándose dentro de esa frontera y no puede competir directamente con elementos externos.

### “El tooltip se corta aunque tenga un nivel alto”

Busca un ancestro que recorte la pintura. El orden de apilamiento y el recorte son mecanismos distintos.

### “Todo se arregla con números cada vez mayores”

Eso suele ocultar una estructura de contextos mal entendida. Define una escala de capas y corrige el contexto que impide la comparación correcta.

## En resumen

- `z-index` ordena cajas dentro de un contexto; no es una escala global.
- Un contexto de apilamiento se compara como una unidad frente a sus hermanos.
- Un descendiente con `z-index: 9999` no puede escapar del contexto de su ancestro.
- `position`, flexbox y grid influyen en cuándo `z-index` puede aplicarse.
- `opacity`, transformaciones, filtros, aislamiento y contención pueden crear contextos nuevos.
- El stacking order también depende del tipo de caja y del orden del documento.
- El recorte por `overflow` no se corrige con `z-index`.
- Para depurar, inspecciona primero geometría, ancestros, contextos y recortes; después ajusta los niveles.
