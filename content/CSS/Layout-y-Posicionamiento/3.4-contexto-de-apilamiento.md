# 3.4. Contexto de apilamiento

Cuando varias cajas se superponen, el navegador necesita decidir cuál se pinta delante. `z-index` influye en ese orden, pero no es una escala global: los elementos se comparan primero dentro de sus contextos de apilamiento.

## El valor de `z-index`

`z-index` acepta valores enteros y también `auto`. Un valor mayor suele pintar la caja delante de otra dentro del mismo contexto de apilamiento.

```css
.menu {
  position: relative;
  z-index: 2;
}

.panel {
  position: relative;
  z-index: 1;
}
```

En este caso, si ambas cajas pertenecen al mismo contexto, `.menu` se pinta delante de `.panel` donde se superponen.

`z-index` no tiene efecto en todos los elementos de la misma forma. Es común que se aplique a elementos posicionados y a elementos flex o grid. Además, otros valores de CSS pueden crear contextos nuevos, incluso cuando no se ha escrito un `z-index` grande.

## ¿Qué es un contexto de apilamiento?

Un contexto de apilamiento es un grupo independiente de elementos que se ordena como una unidad frente a los demás grupos. Los descendientes compiten por el orden dentro de ese contexto, pero sus valores no se comparan directamente con elementos que pertenecen a otro contexto.

```css
.contenedor-a {
  position: relative;
  z-index: 1;
}

.contenedor-a .hijo {
  position: absolute;
  z-index: 9999;
}

.contenedor-b {
  position: relative;
  z-index: 2;
}
```

Aunque el hijo tenga `z-index: 9999`, el grupo `.contenedor-a` está por debajo de `.contenedor-b`. El hijo no puede salir de su contexto para adelantar a ese otro grupo.

## Propiedades que pueden crear contextos

Algunas causas frecuentes son:

- `position: relative` o `absolute` junto con un `z-index` distinto de `auto`;
- `position: fixed` o `sticky`;
- un elemento flex o grid con `z-index` distinto de `auto`;
- `opacity` menor que `1`;
- propiedades como `transform`, `filter` o `perspective` con un valor distinto de `none`;
- `isolation: isolate`.

La lista completa depende de las reglas de CSS que se apliquen, así que al depurar conviene revisar los estilos calculados y los ancestros del elemento.

## Orden de apilamiento, en términos prácticos

El navegador pinta distintas categorías de contenido siguiendo reglas de orden. Como modelo simplificado:

1. se pinta el fondo y el borde del elemento que crea el contexto;
2. se pintan elementos en el flujo normal;
3. se pintan elementos posicionados y contextos descendientes siguiendo su orden de apilamiento;
4. dentro del mismo nivel, el orden del documento puede decidir qué elemento aparece delante.

No se debe reducir todo el orden de pintura a “el número más grande siempre gana”. Primero identifica el contexto de cada elemento; luego compara los niveles dentro de ese contexto.

## Depuración visual

Cuando una caja aparece detrás de otra:

1. Selecciona el elemento en las herramientas de desarrollo y revisa `position`, `z-index`, `opacity` y propiedades como `transform`.
2. Inspecciona los ancestros: alguno puede estar creando un contexto de apilamiento.
3. Compara los contextos de los dos elementos que se superponen antes de cambiar sus valores.
4. Comprueba si `overflow` recorta la caja; un `z-index` no puede hacer que el contenido escape de un recorte.
5. Activa temporalmente bordes o colores de fondo para reconocer qué cajas y contenedores se están superponiendo.

Evita resolver cada superposición con números arbitrariamente enormes. Una escala pequeña y documentada es más fácil de mantener:

```css
:root {
  --layer-content: 0;
  --layer-dropdown: 10;
  --layer-sticky: 20;
  --layer-modal: 30;
}
```

Los valores solo se comparan cuando corresponde; las variables hacen más legible la intención, pero no eliminan los límites de los contextos.

## En resumen

- `z-index` influye en el orden de pintura dentro de un contexto.
- Los contextos de apilamiento son independientes y sus descendientes no pueden competir fuera de ellos.
- Varios estilos además de `z-index` pueden crear contextos.
- Para depurar, empieza por los ancestros, el contexto y el recorte, no por aumentar el número.
