# 3.2. `display`

La propiedad `display` define cómo participa la caja de un elemento en el layout. No es únicamente un interruptor para “mostrar” u “ocultar”: determina el tipo de caja que genera el elemento, cómo se coloca respecto a sus hermanos y qué modelo se usa para organizar a sus hijos.

Al leer `display`, conviene separar dos preguntas:

1. **¿Cómo se comporta la caja del elemento frente a sus hermanos?** Es su comportamiento exterior: por ejemplo, como bloque o dentro de una línea.
2. **¿Cómo se organizan los hijos del elemento?** Es su comportamiento interior: por ejemplo, con flujo normal, flexbox o grid.

Esta distinción permite entender por qué existen combinaciones como `inline-flex` y `block grid`.

## 1. `display` y las cajas CSS

HTML define estructura y significado. CSS define presentación. Cada elemento HTML tiene estilos iniciales del navegador; entre ellos, un valor de `display`. Por eso un `p` suele iniciar como bloque y un `a` suele iniciar en línea.

Una regla CSS puede reemplazar ese valor inicial:

```html
<span class="aviso">Aviso importante</span>
```

```css
.aviso {
  display: block;
}
```

El `span` ahora genera una caja de bloque, pero semánticamente sigue siendo el mismo `span`. Cambiar `display` no cambia el significado del HTML, los roles accesibles ni el orden del documento.

En términos prácticos, `display` afecta:

- si la caja empieza una línea nueva o comparte una línea;
- cómo se calculan y respetan su ancho, alto, relleno, bordes y márgenes;
- cómo se acomodan los hijos directos;
- si se genera una caja visible o ninguna caja;
- cómo interactúa el elemento con el flujo normal.

Los detalles exactos dependen también de las demás propiedades, del elemento y del contexto de formato.

## 2. `block`: una caja de bloque

`display: block` hace que el elemento genere una caja de bloque. En el flujo normal de bloques, una caja se coloca después de la anterior en el eje de bloque. En escritura horizontal habitual, esto se ve como una caja debajo de otra.

```html
<div class="bloque">Primer bloque</div>
<div class="bloque">Segundo bloque</div>
```

```css
.bloque {
  display: block;
  padding: 1rem;
  border: 1px solid #64748b;
}
```

Con ancho `auto`, una caja de bloque suele ocupar el espacio disponible de su bloque contenedor, teniendo en cuenta márgenes, bordes y relleno. Esto no significa que el texto se estire hasta ambos bordes: la caja puede ser ancha aunque su texto solo ocupe parte de ella.

```css
.lectura {
  display: block;
  inline-size: min(100%, 40rem);
  margin-inline: auto;
}
```

Un bloque puede tener `width`, `height`, `min-width`, `max-width`, `padding` y `border`. Si se usa `box-sizing: content-box`, ancho y alto normalmente describen el área de contenido y el relleno y el borde se añaden por fuera; con `border-box`, se incluyen en las dimensiones declaradas. `display: block` no cancela las reglas del modelo de caja.

### Bloque no significa ancho fijo ni alto fijo

El ancho `auto` de un bloque en flujo suele adaptarse al espacio disponible. La altura, en cambio, suele ajustarse al contenido. Si el contenido aumenta y puede envolverse, la caja normalmente crece; si se fuerza una altura pequeña, el contenido puede desbordarse.

```css
.tarjeta {
  display: block;
  inline-size: 20rem;
  /* La altura puede crecer según el contenido. */
}
```

Los márgenes verticales de bloques en flujo normal pueden colapsar bajo ciertas condiciones. Los márgenes no colapsan entre elementos flex o grid de la misma manera. Para los detalles del colapso, consulta [3.1. Flujo normal](3.1-flujo-normal.md).

## 3. `inline`: una caja en el formato de texto

`display: inline` hace que el elemento participe en el formato en línea: se coloca dentro de una línea de texto junto a palabras y otros elementos en línea.

```html
<p>
  Aprende <strong>CSS</strong> y consulta
  <a href="/recursos">los recursos</a>.
</p>
```

Los elementos `strong` y `a` suelen mostrarse en línea. Si no hay suficiente espacio, el navegador puede continuar el texto en la siguiente línea. El elemento en línea puede fragmentarse entre líneas; su fondo y bordes pueden pintarse alrededor de cada fragmento.

### Dimensiones y márgenes en elementos en línea

Para una caja en línea **no reemplazada**, `width` y `height` no la convierten en una caja de tamaño fijo como lo harían con un bloque. Los márgenes en el eje de bloque tampoco desplazan las líneas adyacentes como se espera de un bloque.

```css
.resaltado {
  display: inline;
  width: 20rem; /* No establece el ancho de una caja inline no reemplazada. */
  height: 4rem; /* Tampoco establece su altura como un bloque. */
}
```

Los márgenes y el relleno en el eje en línea sí pueden afectar la separación horizontal. El relleno, el borde y el fondo en el eje de bloque pueden dibujarse alrededor del texto, pero no generan el mismo tipo de separación de líneas que produciría una caja de bloque.

Hay excepciones: elementos reemplazados como `img` e `input` se comportan como contenido en línea en muchos contextos y sí pueden aceptar dimensiones. Por eso la limitación anterior no debe generalizarse a todo elemento que visualmente esté en una línea.

Si una pieza de contenido necesita ancho, alto y relleno consistentes y debe continuar dentro de una línea, considera `inline-block`. Si debe ocupar su propia fila, considera `block`.

## 4. `inline-block`: caja dimensionable que participa en una línea

`inline-block` combina dos tipos de comportamiento:

- **Exterior en línea**: el elemento comparte una línea con texto y otras cajas en línea.
- **Interior de bloque**: el contenido se organiza en una caja de bloque que admite dimensiones y espaciado.

```html
<p>
  El estado es
  <span class="etiqueta">En revisión</span>
  desde esta mañana.
</p>
```

```css
.etiqueta {
  display: inline-block;
  padding: 0.2em 0.65em;
  border: 1px solid currentColor;
  border-radius: 999px;
}
```

La etiqueta acepta `width`, `height`, `padding` y bordes. Sin embargo, en la línea se comporta como una unidad: si no cabe al final de la línea, normalmente salta completa a la siguiente en vez de fragmentar su caja entre líneas.

Por defecto, un `inline-block` suele alinearse por la línea base. Cajas de distintas alturas pueden parecer desalineadas. `vertical-align` permite ajustar su alineación en la línea:

```css
.icono {
  display: inline-block;
  inline-size: 1em;
  block-size: 1em;
  vertical-align: middle;
}
```

Los espacios y saltos de línea entre elementos `inline-block` en el HTML suelen convertirse en espacios visibles. Si los elementos forman una colección, flexbox con `gap` suele ser más fácil de controlar.

### Comparación directa

| Característica | `block` | `inline` | `inline-block` |
|---|---|---|---|
| Empieza normalmente en una nueva línea | Sí | No | No |
| Comparte una línea con texto | No | Sí | Sí |
| Admite ancho y alto como caja | Sí | No para cajas inline no reemplazadas | Sí |
| Puede fragmentarse entre líneas | Su contenido puede ocupar muchas líneas | Sí | La caja se mantiene como unidad |
| Caso de uso común | Secciones, párrafos, contenedores | Énfasis y enlaces en una frase | Etiquetas y controles pequeños en línea |

Esta tabla resume el comportamiento habitual en flujo normal. Un elemento puede participar en otros contextos de formato, y propiedades como `position`, `float`, flex o grid pueden cambiar la composición.

## 5. `display: none`: no se genera una caja

`display: none` indica que el elemento no debe generar una caja de presentación. En un flujo normal, el espacio que habría ocupado desaparece y los elementos siguientes se componen como si esa caja no estuviera presente.

```html
<p>Uno</p>
<p class="mensaje">Este mensaje está oculto.</p>
<p>Tres</p>
```

```css
.mensaje {
  display: none;
}
```

El segundo párrafo no reserva espacio; “Tres” se coloca después de “Uno”, respetando el espaciado que le corresponda. `display: none` no equivale a poner `visibility: hidden` ni a usar `opacity: 0`.

### `display: none` frente al atributo `hidden`

El atributo HTML `hidden` expresa que el contenido no es actualmente relevante y normalmente hace que el navegador no lo presente. CSS puede interferir con su presentación: una regla explícita de `display` puede sobreescribir el estilo de navegador asociado al atributo en ciertos casos.

Usa el mecanismo que exprese la intención del componente y evita declarar un `display` visible accidentalmente sobre un elemento que debe seguir oculto. En una interfaz con estados, comprueba los estilos computados y el comportamiento al cambiar de estado.

## 6. `visibility: hidden`: la caja permanece

`visibility: hidden` oculta el elemento visualmente, pero conserva la caja y el espacio que ocupa en el layout.

```css
.mensaje {
  visibility: hidden;
}
```

En el ejemplo anterior, el párrafo “Tres” permanece en la misma posición que tendría si el mensaje fuera visible; queda un espacio vacío donde está la caja oculta.

La propiedad se hereda. Un descendiente puede declarar `visibility: visible` y volver a mostrarse aunque un ancestro tenga `visibility: hidden`, siempre que las demás condiciones de presentación lo permitan. El espacio de la caja del ancestro se conserva.

`visibility: collapse` tiene comportamientos especiales para filas y columnas de tablas y puede comportarse como `hidden` en otros casos. No es un reemplazo general de `display: none`.

## 7. `opacity: 0` no es una forma equivalente de ocultar

`opacity: 0` hace transparente el elemento y su contenido, pero no elimina su caja ni necesariamente su interacción:

```css
.transparente {
  opacity: 0;
}
```

El elemento normalmente sigue reservando espacio, puede recibir clics y, si contiene controles enfocables, puede seguir entrando en el orden de foco. Además, la opacidad menor que `1` crea un contexto de apilamiento.

Si se oculta un panel interactivo solo mediante opacidad, una persona podría tabular hasta controles invisibles o activar algo que no ve. El cambio visual debe coordinarse con la interacción y el estado accesible: por ejemplo, controlar cuándo el contenido se puede enfocar, interactuar y exponer a tecnologías de asistencia.

## 8. Comparación: caja, espacio e interacción

| Técnica | ¿Se genera caja? | ¿Reserva espacio? | ¿Se ve? | Nota |
|---|---:|---:|---:|---|
| `display: none` | No | No | No | El elemento deja de participar visualmente en el layout. |
| `visibility: hidden` | Sí | Sí | No | Conserva el espacio; los descendientes pueden sobrescribir visibilidad. |
| `opacity: 0` | Sí | Sí | No | Puede seguir recibiendo clics o foco. |
| `display: block` / visible | Sí | Sí | Sí, salvo otros estilos | La caja participa según el contexto de layout. |

La tabla describe principalmente presentación y layout. No es una especificación suficiente del árbol de accesibilidad para todos los navegadores y tecnologías de asistencia. Si el requisito es ocultar contenido de lectores de pantalla, conservarlo en ellos o retirarlo del orden de foco, hay que elegir y verificar un patrón accesible específico.

### Ocultar contenido no es lo mismo que retirar funcionalidad

Antes de ocultar un elemento, decide qué debe ocurrir con:

- el espacio del layout;
- la posibilidad de hacer clic, tocar o activar el elemento;
- la posibilidad de enfocarlo con teclado;
- su exposición a tecnologías de asistencia;
- la posibilidad de que una transición muestre u oculte el contenido.

No existe una sola propiedad CSS que resuelva todas esas decisiones. Para menús, diálogos, paneles y pestañas, el estilo visual debe mantenerse sincronizado con el estado y el comportamiento del componente.

## 9. El impacto de `display` en el flujo

`display` cambia qué cajas participan en el layout y de qué manera:

- `block` ocupa su lugar en el flujo de bloques y afecta la posición de los elementos siguientes;
- `inline` se compone dentro de las líneas de texto y puede fragmentarse;
- `inline-block` ocupa una caja dimensionable dentro de la línea;
- `none` no genera caja, por lo que no reserva espacio;
- `visibility: hidden` y `opacity: 0` conservan la caja y su espacio;
- flex y grid cambian cómo se distribuyen los hijos directos del contenedor.

Con `display: none`, al cambiar la propiedad a un valor visible, el elemento vuelve a participar en el layout y puede desplazar contenido. En cambio, cambiar `visibility` u `opacity` no suele reacomodar a los hermanos porque el espacio ya estaba reservado.

La posición también importa. Un elemento puede conservar un valor como `display: block` y, aun así, dejar de reservar su espacio habitual si se saca del flujo con posicionamiento absoluto. Del mismo modo, los flotantes interactúan con el flujo de una manera distinta. No atribuyas todos los cambios de posición exclusivamente a `display`.

## 10. Los valores modernos: comportamiento exterior e interior

Una forma útil de entender muchos valores de `display` es distinguir:

- **tipo exterior (*outer display type*)**: cómo participa la caja con respecto a sus hermanos;
- **tipo interior (*inner display type*)**: cómo organiza a sus propios hijos.

Por ejemplo:

```css
.barra {
  display: flex;
}
```

En la mayoría de los casos, `display: flex` se comporta como `block flex`: exteriormente participa como un bloque; interiormente distribuye a sus hijos directos con flexbox.

CSS permite expresar explícitamente ambos aspectos:

```css
.barra-de-linea {
  display: inline flex;
}

.zona-de-tarjetas {
  display: block grid;
}
```

Los valores de dos palabras hacen explícita la combinación exterior/interior. Las formas tradicionales `inline-flex` y `inline-grid` siguen siendo comunes y ampliamente reconocibles:

```css
.barra-de-linea {
  display: inline-flex;
}

.zona-de-tarjetas {
  display: grid;
}
```

La disponibilidad y el soporte de valores concretos deben verificarse contra los navegadores del proyecto. En ejemplos generales, las formas conocidas `flex`, `inline-flex`, `grid` e `inline-grid` suelen ser fáciles de leer.

## 11. Flexbox: hijos organizados en una dimensión

`display: flex` crea un contenedor flex. El contenedor se coloca normalmente como bloque en su padre y sus **hijos directos** se convierten en elementos flex. Estos se distribuyen a lo largo de un eje principal y se pueden alinear en el eje transversal.

```html
<nav class="navegacion">
  <a href="/">Inicio</a>
  <a href="/cursos">Cursos</a>
  <a href="/acerca">Acerca de</a>
</nav>
```

```css
.navegacion {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 1rem;
}
```

El valor `gap` crea separación entre elementos del contenedor sin recurrir a márgenes enfrentados. `flex-wrap: wrap` permite que los elementos continúen en otra fila si no caben; sin wrap, la distribución puede reducir elementos o desbordar, dependiendo de las restricciones.

Solo los hijos directos son elementos flex. Los nietos mantienen el formato interno definido por sus propios contenedores:

```html
<div class="fila">
  <article>
    <h2>Título</h2>
    <p>El contenido del artículo conserva su propio layout.</p>
  </article>
</div>
```

## 12. Grid: hijos organizados en filas y columnas

`display: grid` crea un contenedor grid. Sus hijos directos se colocan en una cuadrícula de filas y columnas explícitas o implícitas.

```css
.tarjetas {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: 1rem;
}
```

Grid es útil cuando importa la relación en dos dimensiones o cuando se quieren definir columnas y filas coordinadas. Como con flex, son los hijos directos los que se vuelven grid items; el contenido dentro de cada tarjeta mantiene su propio contexto interno.

### ¿Flexbox o grid?

- Elige **flexbox** cuando la distribución principal sea en una dimensión: una fila de controles, una barra de navegación o acciones.
- Elige **grid** cuando quieras organizar una colección en filas y columnas o controlar una estructura bidimensional.
- Ninguno es “solo para una fila” o “solo para una página completa”: elige el modelo que expresa de forma más clara la relación entre los elementos.

## 13. Otras combinaciones y valores que conviene reconocer

### `flow-root`

`display: flow-root` crea un contexto de formato de bloque. El elemento se comporta exteriormente como bloque y contiene el flujo interno, incluyendo flotantes. Puede ser una alternativa clara cuando se necesita que un contenedor incluya un hijo flotante.

```css
.contenedor {
  display: flow-root;
}
```

También inicia un límite para el colapso de márgenes de sus hijos con el exterior. No lo uses de manera automática: el nuevo contexto puede tener consecuencias en el layout.

### `list-item`

`display: list-item` genera una caja principal y una caja de marcador, como la viñeta o numeración de una lista. Es el comportamiento que suelen tener los elementos `li`. Usarlo no convierte un elemento arbitrario en una lista semántica; para una lista, el HTML apropiado sigue siendo `ul`, `ol` y `li`.

### `table`

Valores como `table`, `table-row` y `table-cell` generan comportamientos de layout tabular. Son útiles para entender el layout de una tabla y algunas presentaciones, pero no sustituyen la semántica de una tabla HTML cuando el contenido es realmente tabular.

### `contents`

`display: contents` hace que, en términos de cajas CSS, el elemento no genere su caja principal y que sus hijos participen en el formato como si esa caja se hubiera retirado. No significa que el nodo HTML se borre del DOM.

Esto puede ser útil en composiciones específicas, pero puede cambiar la relación entre estructura visual y estructura accesible. El soporte y el comportamiento en árboles de accesibilidad han tenido diferencias entre navegadores, particularmente para elementos semánticos. No lo apliques indiscriminadamente a `nav`, `button`, listas u otros elementos con significado: comprueba el soporte actual, la navegación por teclado y el resultado con tecnologías de asistencia.

## 14. `display` y animaciones

Históricamente se ha tratado `display` como una propiedad que no se anima entre `none` y un valor visible. En CSS moderno, existen mecanismos para coordinar transiciones discretas de propiedades como `display` con otras propiedades visuales, pero hay que aplicar la sintaxis y las condiciones adecuadas, además de considerar compatibilidad.

Para un curso básico, no dependas de una transición de `display` sin verificarla. Una estrategia puede animar propiedades como `opacity` y `transform`, mientras gestiona por separado cuándo el contenido se puede enfocar e interactuar. Una transición puramente visual no resuelve el estado accesible del componente.

## 15. Ejemplo: mismo HTML, varios layouts

El mismo grupo de enlaces puede convertirse en bloques apilados, una fila flexible o una cuadrícula, sin alterar el HTML:

```html
<nav class="enlaces">
  <a href="/inicio">Inicio</a>
  <a href="/guias">Guías</a>
  <a href="/ejercicios">Ejercicios</a>
</nav>
```

```css
/* Opción 1: enlaces en bloques, uno debajo de otro. */
.enlaces--lista a {
  display: block;
  padding: 0.5rem;
}

/* Opción 2: colección en una dimensión. */
.enlaces--fila {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
}

/* Opción 3: colección en varias columnas. */
.enlaces--rejilla {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 0.75rem;
}
```

Cada regla expresa una composición distinta. La semántica de `nav` y el orden de los enlaces en HTML no cambian. La versión elegida debe permitir que el contenido se adapte a anchos pequeños y no debe introducir una secuencia visual confusa.

## 16. Inspección y diagnóstico

Si un elemento no aparece donde esperabas:

1. Inspecciona el valor **computado** de `display`; puede venir del navegador, de una hoja de estilos heredada o de una regla más específica.
2. Comprueba si el elemento genera caja: una regla `display: none` puede haberla eliminado.
3. Revisa el valor del contenedor padre: ¿es flex, grid o un formato de tabla?
4. Comprueba si estás mirando un hijo directo o un descendiente más profundo; solo los hijos directos se convierten en flex items o grid items.
5. Revisa ancho, alto, `min-*`, `max-*`, `box-sizing`, `margin`, `padding`, `overflow` y saltos de línea.
6. Para contenido oculto, verifica por separado espacio, apariencia, foco e interacción.

Puedes activar temporalmente un contorno para distinguir cajas:

```css
* {
  outline: 1px solid rgb(220 38 38 / 25%);
}
```

`outline` no ocupa espacio. El contorno puede ayudarte a identificar una caja, pero no te dice por sí solo si su espacio exterior procede del margen o si el layout lo genera el padre.

## 17. Errores frecuentes

### “`display: block` hace que el elemento sea semánticamente una sección”

No. Cambia la presentación; no cambia el significado HTML ni crea una nueva relación semántica.

### “`display: inline` significa que no se puede aplicar ningún espaciado”

No. El espacio en el eje en línea sí puede cambiar. Lo que no se comporta como una caja de bloque son, entre otros, el ancho, el alto y los márgenes del eje de bloque en un inline no reemplazado.

### “`inline-block` siempre queda centrado verticalmente con el texto”

No. Normalmente se alinea por la línea base. Ajusta `vertical-align` cuando la composición lo requiera.

### “`visibility: hidden` libera el espacio”

No. La caja permanece y reserva espacio. Para retirar la caja del layout se usa `display: none`.

### “`opacity: 0` hace que un componente deje de ser interactivo”

No. El elemento puede seguir recibiendo foco e interacción. Un control transparente pero activo puede ser inaccesible o confuso.

### “`display: flex` convierte todos los descendientes en flex items”

No. Solo convierte a los hijos directos en flex items. Cada hijo puede tener su propio layout interno.

### “Un número grande de propiedades `display` equivale a muchas etiquetas HTML”

No. Los valores de display definen cajas y formatos CSS; no reescriben el DOM ni su semántica.

## En resumen

- `display` determina cómo participa la caja de un elemento y cómo organiza a sus hijos.
- `block`, `inline` e `inline-block` se distinguen por su participación en bloques y líneas, y por las dimensiones que admiten.
- `display: none` retira la caja; `visibility: hidden` y `opacity: 0` conservan el espacio, pero difieren en interacción y apilamiento.
- Flex y grid crean contextos internos para sus hijos directos; el contenedor sigue participando en el layout exterior.
- Los valores modernos se entienden mejor separando el comportamiento exterior del interior.
- La semántica HTML, la visibilidad, el flujo y la accesibilidad son aspectos relacionados, pero no intercambiables.
