# 3.3. `position`

La propiedad `position` responde a dos preguntas diferentes:

1. **¿El elemento sigue participando en el flujo normal?** Es decir, ¿su caja sigue reservando espacio y empujando a sus hermanos?
2. **¿Desde qué caja se calculan sus desplazamientos?** Esa caja es su **bloque contenedor** para el posicionamiento.

Esta distinción conecta con [3.1. Flujo normal](3.1-flujo-normal.md): `display` puede definir el tipo de caja, pero `position` decide si esa caja conserva su lugar normal o se coloca con reglas especiales. También conecta con [3.2. `display`](3.2-display.md): un elemento puede seguir teniendo `display: block` y, aun así, dejar de reservar su espacio si usa `absolute` o `fixed`.

## 1. Insets: cómo se expresa un desplazamiento

Los insets son las propiedades `top`, `right`, `bottom` y `left`, junto con sus equivalentes lógicos `inset-block-start`, `inset-block-end`, `inset-inline-start` e `inset-inline-end`. Indican distancias desde los lados del bloque contenedor.

```css
.elemento {
  position: relative;
  inset-block-start: 0.5rem;
  inset-inline-start: 1rem;
}
```

En este ejemplo, el elemento se pinta desplazado hacia el inicio del eje de bloque y del eje en línea. La dirección exacta depende del modo de escritura (`writing-mode`), por eso las propiedades lógicas suelen ser más resistentes que `top` y `left`.

Un inset no equivale a un margen:

- el margen modifica la separación que usa el layout;
- un inset modifica la posición de una caja posicionada respecto a su referencia;
- con `relative`, el espacio original se conserva;
- con `absolute` y `fixed`, la caja deja de ocupar su lugar normal.

Cuando no se declara un inset, su valor computado suele ser `auto` y el navegador conserva la posición determinada por el layout o resuelve la posición a partir de los otros insets y del tamaño disponible. Declarar `inset: 0` es distinto: fija los cuatro lados y puede hacer que una caja se estire hasta llenar su bloque contenedor.

## 2. `static`: participar normalmente

`static` es el valor inicial de `position`. El elemento participa en el flujo normal, por lo que los hermanos se colocan teniendo en cuenta su caja. Los insets no lo desplazan y `z-index` no le da un nivel de apilamiento por el mero hecho de ser `static`.

```css
.parrafo {
  position: static;
  inset-block-start: 2rem; /* No produce un desplazamiento. */
}
```

Normalmente no es necesario escribir `position: static`; resulta útil para restablecer un valor heredado por una regla más específica o para devolver un componente a su comportamiento de flujo.

## 3. `relative`: desplazar conservando el hueco

`relative` parte de la posición que el elemento tendría en el flujo normal. Después permite desplazar la caja visualmente mediante insets. El hueco original no se mueve ni se elimina: los elementos siguientes siguen componiéndose como si la caja continuara en su posición inicial.

```html
<p class="nota">Esta nota conserva su lugar en el flujo.</p>
<p>Este párrafo no sube aunque la nota se desplace.</p>
```

```css
.nota {
  position: relative;
  inset-inline-start: 1rem;
}
```

El desplazamiento puede hacer que la caja se superponga a otras. No cambia el cálculo de las cajas vecinas, así que no es una técnica apropiada para crear un espaciado nuevo; para eso usa `margin`, `padding`, `gap` o un layout flex/grid, según la relación descrita en [3.1. Flujo normal](3.1-flujo-normal.md).

### `relative` como referencia local

Un uso muy importante de `relative` es crear un bloque contenedor para un descendiente absoluto, incluso sin desplazar el propio elemento:

```html
<article class="tarjeta">
  <h2>Noticia</h2>
  <span class="estado">Nuevo</span>
</article>
```

```css
.tarjeta {
  position: relative;
}

.estado {
  position: absolute;
  inset-block-start: 1rem;
  inset-inline-end: 1rem;
}
```

Ahora `.estado` se calcula respecto a `.tarjeta`, no respecto a toda la página. Esta pareja es útil para insignias, iconos, botones de cerrar y adornos que pertenecen a un componente. El contenedor debe tener una geometría que haga sentido, a menudo con un tamaño definido por su contenido, `min-block-size` o una relación de aspecto.

## 4. `absolute`: una caja fuera del flujo

`absolute` retira la caja del flujo normal. Sus hermanos se colocan como si el elemento no ocupara una posición, por lo que no lo empuja ni deja un hueco para él. La caja puede superponerse a contenido y necesita una referencia espacial explícita.

### El bloque contenedor

Para un elemento absoluto, el navegador busca hacia arriba el ancestro que establece el bloque contenedor. El caso más habitual es el ancestro más cercano cuyo `position` no sea `static` (`relative`, `absolute`, `fixed` o `sticky`). Algunas propiedades, como `transform`, `filter`, `perspective` o ciertos valores de `contain`, también pueden cambiar la referencia.

```css
.panel {
  position: relative;
  padding: 1rem;
}

.cerrar {
  position: absolute;
  inset-block-start: 0.5rem;
  inset-inline-end: 0.5rem;
}
```

El botón `.cerrar` se coloca dentro de `.panel`. Si se elimina `position: relative` del panel, el navegador continúa buscando otro ancestro adecuado; si no encuentra ninguno, puede terminar usando el bloque contenedor inicial. Por eso un absoluto que “aparece en la esquina de la página” suele indicar que falta un ancestro de referencia.

El tamaño también importa. Con `inset-inline-start: 0` e `inset-inline-end: 0`, por ejemplo, una caja con tamaño automático puede extenderse entre ambos lados disponibles. Con un ancho explícito y los dos insets del mismo eje, las restricciones pueden resultar incompatibles; el navegador debe resolver el exceso según la dirección de escritura y las reglas de posicionamiento. Es más claro fijar solo las restricciones necesarias.

### Cuándo usarlo

`absolute` es adecuado cuando una pieza pertenece visualmente a otra y debe superponerse: una insignia dentro de una tarjeta, un icono dentro de un campo o un menú desplegable anclado a su botón. No es un sustituto general de flexbox, grid o del flujo normal. Si cada bloque de una página se coloca con coordenadas, el contenido deja de adaptarse bien a textos largos, zoom, traducciones y pantallas estrechas.

## 5. `fixed`: anclado al viewport

`fixed` también retira la caja del flujo, pero normalmente calcula su posición respecto al **viewport** o bloque contenedor inicial. Por eso un elemento fijo mantiene su posición mientras se desplaza el documento.

```css
.boton-ayuda {
  position: fixed;
  inset-block-end: 1rem;
  inset-inline-end: 1rem;
}
```

Este patrón sirve para controles persistentes, como una acción de ayuda o una barra que debe permanecer visible. No reserva espacio para sí misma: puede cubrir el contenido que queda debajo. En dispositivos con zonas seguras conviene considerar `env(safe-area-inset-*)` y comprobar el resultado con zoom y teclado virtual.

Un ancestro con `transform`, `filter`, `perspective` o determinadas formas de contención puede establecer el bloque contenedor del elemento fijo. En ese caso deja de comportarse como un elemento anclado directamente a la ventana. Si un `fixed` se mueve junto con una tarjeta o queda limitado a ella, inspecciona esas propiedades en todos sus ancestros.

## 6. `sticky`: en flujo, pero adherente

`sticky` combina dos comportamientos:

- inicialmente participa en el flujo normal y conserva su espacio;
- al alcanzar un umbral definido por un inset, se desplaza de forma adherente dentro de los límites de su contenedor.

```css
.encabezado-seccion {
  position: sticky;
  inset-block-start: 0;
  z-index: 1;
  background: white;
}
```

El encabezado no se queda pegado para siempre ni escapa de su sección. Cuando el contenedor termina, el encabezado también deja de estar adherido. Esta es la diferencia esencial con `fixed`: `fixed` se separa del flujo y normalmente se relaciona con el viewport; `sticky` conserva su lugar y está limitado por un contenedor.

### Qué necesita `sticky`

Para que el efecto sea visible:

- debe existir al menos un inset en el eje de desplazamiento, como `inset-block-start: 0`;
- debe haber espacio suficiente para desplazar el elemento dentro de su contenedor;
- el contenedor debe tener un recorrido de desplazamiento real;
- el elemento no debe ser tan alto que no quepa en el área útil del contenedor;
- su fondo y, si hace falta, un `z-index` deben evitar que el contenido que pasa por debajo se mezcle visualmente.

Un ancestro con `overflow: auto`, `scroll` o `hidden` puede convertirse en el contenedor de desplazamiento relevante, aunque no sea el elemento que la persona desplaza de forma visible. Esto explica muchos casos en los que `sticky` parece no funcionar: el `sticky` está adherido dentro de una caja que no tiene suficiente altura o que no se desplaza. La diferencia entre un contenedor de desplazamiento y un simple recorte depende de cómo se haya configurado `overflow`.

## 7. Comparación rápida

| Valor | ¿Participa en el flujo? | Referencia habitual | ¿Conserva su espacio? | Uso típico |
|---|---:|---|---:|---|
| `static` | Sí | Layout normal | Sí | Comportamiento por defecto |
| `relative` | Sí | Su posición normal | Sí | Desplazamiento pequeño o referencia local |
| `absolute` | No | Ancestro posicionador | No | Superposición dentro de un componente |
| `fixed` | No | Viewport o ancestro especial | No | Control persistente en la ventana |
| `sticky` | Sí | Contenedor de desplazamiento | Sí | Encabezado que se adhiere durante el scroll |

La pregunta “¿dónde está?” no basta. Para razonar sobre un elemento hay que preguntar también “¿qué espacio reserva?”, “¿quién es su bloque contenedor?” y “¿qué caja limita su desplazamiento?”.

## 8. Posicionamiento, `z-index` y contexto de apilamiento

Posicionar una caja y decidir quién se pinta delante son problemas relacionados, pero no idénticos. `position` puede sacar una caja del flujo; `z-index` influye en el orden de pintura cuando se superpone con otras.

```css
.menu {
  position: absolute;
  z-index: 10;
}
```

Un `z-index` alto no es una escala global. Los elementos se comparan dentro de su **contexto de apilamiento**. Si un ancestro crea un contexto con un nivel inferior, un descendiente con `z-index: 9999` no puede saltar por encima de otro contexto hermano que esté por delante.

Además de elementos posicionados con `z-index` distinto de `auto`, pueden crear contextos propiedades como `position: fixed`, `position: sticky`, `opacity` menor que `1`, `transform`, `filter` e `isolation: isolate`. El recorte de `overflow` tampoco se soluciona aumentando `z-index`: una caja recortada sigue estando recortada.

Para depurar una superposición, inspecciona en este orden:

1. identifica si el elemento está en flujo o fuera de él;
2. localiza su bloque contenedor y sus insets;
3. revisa los ancestros que puedan crear contextos de apilamiento o recortes;
4. compara `z-index` dentro del mismo contexto;
5. comprueba el orden del documento y el tamaño real de las cajas.

El orden de pintura se entiende a partir de los contextos que crean los ancestros y de la posición relativa de las cajas dentro de cada contexto.

## 9. Errores frecuentes y diagnóstico

### “`top` no funciona”

Comprueba que el elemento no sea `position: static`. Un inset no desplaza un elemento estático. Después verifica que el desplazamiento se declare en el eje correcto y que no esté siendo sobreescrito por una regla más específica.

### “El absoluto se coloca respecto a la página”

Busca el ancestro más cercano que deba ser la referencia y dale `position: relative` si corresponde. No añadas offsets arbitrarios antes de corregir el bloque contenedor.

### “`sticky` no se pega”

Comprueba el inset, la altura del contenedor, la altura del propio elemento y cada ancestro con `overflow`. El ancestro que crea el área desplazable puede no ser el viewport.

### “El `z-index` no lo pone delante”

Revisa contextos de apilamiento y `overflow` antes de aumentar el número. Un valor mayor solo gana frente a elementos comparables dentro del mismo contexto y no atraviesa un recorte.

### “El contenido queda tapado”

Es el resultado esperado cuando se usa `absolute` o `fixed`: esas cajas no reservan espacio. Añade separación al layout, una altura de compensación o cambia a `sticky`/flujo normal si el contenido debe mantener su lugar.

## En resumen

- `static` participa normalmente en el flujo y no responde a insets.
- `relative` permite desplazar visualmente una caja sin perder su espacio y puede crear una referencia local.
- `absolute` sale del flujo y se calcula respecto a un bloque contenedor.
- `fixed` sale del flujo y suele estar anclado al viewport; un ancestro especial puede cambiar esa referencia.
- `sticky` conserva su espacio y se adhiere temporalmente dentro de un contenedor de desplazamiento.
- `z-index` ordena pintura dentro de contextos de apilamiento; no es una escala global.
- Usa el flujo normal, flexbox y grid para la estructura; reserva el posicionamiento para relaciones espaciales concretas.
